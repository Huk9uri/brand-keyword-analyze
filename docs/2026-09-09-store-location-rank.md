# 매장 좌표 기반 키워드 순위 평가 전환

후속 확정: 주 수집 원천은 매장 x·y 좌표를 넣은 플레이스 목록으로 전환한다.
최신 기준은 [플레이스 목록 원천 확정](2026-09-09-place-list-source-decision.md)을 따른다.
아래 V3 통합검색 구현·검증은 이전 단계의 기록이다.

사용자 결정: 매장별 대표키워드 후보를 평가하므로 각 매장 위치에서의 노출을 관측한다.
기존 인계의 좌표 제외 및 매장 간 순위 공유 기준은 신규 수집에 적용하지 않는다.
좌표는 검색 조건이며, 거리나 좌표 자체를 평가 점수로 사용하지 않는다.

## 입력·수집 계약

- 신규 프로필: `MOBILE_STORE_LOCATION_ORGANIC20_V3`.
- 입력 최상위 `rank_profile`과 각 targets의 `search_location`을 지정한다.
- search_location은 latitude, longitude, place_id, source, verified_at으로 구성한다.
- 좌표 범위, Place ID 일치, 출처, 시간대와 기준 시점 이하 검증 시각을 검사한다.
- 누락·잘못된 좌표는 수집 전에 오류로 알린다. IP 위치나 다른 매장 좌표로 대체하지 않는다.
- 같은 메뉴여도 매장별 작업을 만든다. 파일럿은 매장 5개 × 메뉴 5개 = 25건이다.
- 기존 UC·독립 프로필·Selenium을 유지하며 CDP 위치 지정과 위치 권한을 적용한다.
  네이버 검색 페이지의 내위치 활성화 경로를 사용한다.
- 기존 좌표 없는 입력은 오프라인 재현용으로 지원하지만 실수집 명령은 새 프로필을 요구한다.
- 새 평가는 동일 매장·검색어·프로필·좌표의 관측만 선택한다. 좌표 없는 공유 관측을 재사용하지 않는다.

## 원천·적재 연결

기존 순위 스냅샷의 latitude, longitude, location_name을 읽어 실제 저장된 검색 조건을 검증한다.
영수증의 프로필을 바꿔 과거 관측을 새 관측으로 재명명할 수 없다.
결과 카드의 거리 컬럼은 평가 입력에 포함하지 않는다. 별도 DDL은 필요하지 않다.

최신 동결 경로: `outputs/store-location-pilot-20260909T054106Z/`.

- `locations.json`: 5개 매장 좌표 및 Place ID·출처·확인 시각.
- `input.json`: 신규 프로필을 적용한 동결 입력.
- `evaluation.json`: 이 입력으로 생성한 평가와 매장별 수집 큐 25건.
- `source-config.json`: 추후 원천 재수출 설정. 신규 DB 수집 영수증의 run_id·profile·time_offset을
  rank_runs에 추가하고 기준 시점을 갱신한 복사본을 사용한다.

부천본점·강동점·천안쌍용점은 공식 플레이스 페이지의 해당 Place ID 좌표를 확인했다.
선릉역점·신림역점은 기존 Place ID 좌표 캐시를 읽었다. 확인 시각과 원문 HTML을 함께 보존했다.
DB 좌표 캐시에 신규 쓰기는 수행하지 않았다.

## 실제 확인

부천본점 좌표: 위도 37.4835666, 경도 126.7654363.
`설렁탕` 1건을 자동 재시도 없이 실제 UC 브라우저로 확인했다.

- 실행 ID: `e4209125-7b4e-45fe-bcf4-1d2b14853b55`.
- 자연순위 10개, 광고 2개. 부천 지역 검색 결과로 변경됨을 확인했다.
- 한촌설렁탕&갈비 부천본점은 관측된 자연순위 1위다.
- 명시적 끝 표시가 없어 PARTIAL로 보존했다. 자연순위 20개 확보를 의미하지 않는다.
- 로컬 증거만 저장했고 DB 스냅샷 적재는 실행하지 않았다.
- 산출물: 위 동결 경로의 `smoke-e4209125-7b4e-45fe-bcf4-1d2b14853b55/`.

매장별 키워드 평가용 수집 준비는 완료했다. 목록 끝의 판정 기준은 사용자 확인이 아직 남아 있다.
끝이 확인되지 않은 결과라도 관측값과 PARTIAL 상태를 함께 DB에 적재할 수 있다.
