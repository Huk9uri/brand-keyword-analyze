# LLM 입력 구성 개선

## 변경 목적

키워드별 판매수 최상위 매장 한 곳만 전달하던 입력을 매장별 전체 비교 자료로 변경했다. 기존 저장 파일만 읽으며 새 수집이나 유료 API 호출은 수행하지 않았다.

## 구성

- `scope`: 전체 매장 또는 지정 매장. 지정 매장에서는 다른 매장의 조합·변경 기록을 제외한다.
- `analysis_as_of`, `analysis_status`: 분석 기준 시점과 완료·부분 완료 상태.
- `stores`: 대상·제외·판매 관측 없는 매장도 식별 정보와 함께 보존한다.
- 매장별 `keywords`: 후보·기노출·보류를 모두 포함한다. 판매량·매출, 연결된 실제 메뉴명, 검색량·구간·상태·관측일, 순위·노출 상태·관측일·스냅샷 ID를 유지한다.
- `mapping`, `menu_sales`: 연결 규칙과 실제 연결 메뉴별 판매 근거. 같은 메뉴가 다른 키워드에도 연결될 수 있어 합산하지 않는다.
- `quality`, `hold_reasons`, `unmapped_menus`: POS 관측 공백, 순위·검색량 보류 코드, 미연결·모호한 메뉴를 보존한다. 관측 공백의 원인을 적재 지연이라고 단정하지 않는다.
- `search_results`: 해당 관측 스냅샷의 광고 제외 검색 결과. 자체 매장도 포함될 수 있다. `search_results_usable`이 참인 경우만 경쟁 노출 비교에 쓴다. 별도 KeywordList 원본을 신규 연동한 것은 아니다.
- `comparison`: 같은 매장의 이전 대비 변경 내역. 매출 비교 불가 시 기존 null 증감 값을 그대로 유지한다.
- `sources`: 부가 파일의 존재 여부. 부가 파일 누락은 MISSING/null로 표시하며 조용히 0건이라고 해석하지 않는다. 필수 분석 파일은 누락 시 실패한다.
- `facts`: 기존 RUN·QUALITY·키워드 집계와 모든 매장×키워드 근거 ID를 제공한다. 대표 매장 S 근거를 제거하고 `P:매장코드:키워드`로 교체했다.

지역 검색량·실제 유입·클릭·전환 데이터는 없으며 새로 생성하거나 추정하지 않는다.

## 실제 자료 확인

`outputs/menu-keywords-20260917-scheduled`에서 전체 매장 식별 정보 146개와 판매 확인 조합 3,544건을 보존했다. 후보 2,058건, 기노출 922건, 보류 564건이다. 146개 모두 판매 연결이 있다는 뜻은 아니다.

수원인계점 `000110`은 비교 조합 28건을 포함한다. 초기 크기 확인 시 해당 매장 입력은 약 9.4만 자, 전체 입력은 약 1,241만 자였다. 문자 수는 토큰 수가 아니다. 경쟁 결과·미연결 메뉴 등 상세 자료로 인해 입력이 커졌으며, 유료 호출 시 15만 자 초과 입력을 전송 전에 거부한다. 데이터를 임의로 잘라내지 않는다.

## 실행

```powershell
# API 호출 없이 전체 입력 생성
.\.venv\Scripts\python.exe -m scripts.menu_keyword_pipeline.delivery_cli --output outputs/menu-keywords-20260917-scheduled --prepare-input

# 매장별 입력 생성
.\.venv\Scripts\python.exe -m scripts.menu_keyword_pipeline.delivery_cli --output outputs/menu-keywords-20260917-scheduled --store-code 000110 --prepare-input

# 실제 호출 시 매장 지정 — 이 변경 작업에서는 실행하지 않음
.\.venv\Scripts\python.exe -m scripts.menu_keyword_pipeline.delivery_cli --output outputs/menu-keywords-20260917-scheduled --store-code 000110 --model gpt-4.1-mini

# 동일 매장 기준 후보 모델 비교
.\.venv\Scripts\python.exe -m scripts.menu_keyword_pipeline.delivery_cli --output outputs/menu-keywords-20260917-scheduled --store-code 000110 --compare-models
```

매장별 요약은 `store-summaries/<매장코드 해시>`에 분리 저장하며 전체 요약을 덮어쓰지 않는다. 모델 비교도 부가 원자료를 함께 복사하여 입력 범위가 줄어들지 않도록 했다.

## 남은 작업

현재 변경은 입력 구성과 매장별 실행 선택을 다룬다. 기존 출력 JSON·숫자 금지 검증 규칙은 별도 개선 대상이다. 전체 입력을 단일 호출하던 자동 요약은 이제 크기 제한으로 보류되므로, 운영 전 매장별 자동 분할 호출과 전체 보고서 취합을 연결해야 한다. 매장별 요약의 메일 발송은 아직 지원하지 않는다. 매장 입력이 15만 자를 넘으면 추가 분할 설계가 필요하다.

입력 누락·타 매장 혼입·잘못된 순위 상태 해석·원자료 누락 표시·큰 입력의 유료 호출 차단·매장별 출력 분리를 회귀 테스트로 확인한다. 실제 API 추천 품질 및 토큰 비용은 재평가가 필요하다.
