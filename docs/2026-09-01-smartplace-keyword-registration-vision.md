# 네이버 SmartPlace 대표키워드 자동 등록 기능 — 배경과 최종 목표

- 작성일: 2026-09-01
- 대상 프로젝트: `C:\workspace\brand_analyze`
- 대상 브랜드: 육수당, 한촌설렁탕
- 문서 성격: 제품 목표 및 업무 배경 정리
- 현재 상태: 인사이트 리포트와 추천키워드 데이터는 존재하며, 자동 로그인 및 등록 기능은 구현 전

## 1. 한 문장으로 설명하는 최종 목표

> 인사이트 리포트에서 매장별 `5개 등록` 버튼을 누르면, 해당 매장과 추천키워드를 자동으로 확인하고 네이버 SmartPlace에 안전하게 입력한 뒤, 사용자의 최종 확인을 거쳐 대표키워드를 저장할 수 있게 한다.

## 2. 업무 배경

육수당 네이버 플레이스 인사이트 리포트에는 매장별로 추천된 대표키워드 5개가 표시된다.

현재 리포트의 `#s5` 영역에는 매장마다 `5개 복사` 버튼이 있다. 버튼을 누르면 해당 매장의 추천키워드 5개가 클립보드에 줄바꿈 형태로 복사된다.

기존 운영자는 이후 다음 작업을 수기로 수행한다.

```text
리포트에서 매장 확인
→ 추천키워드 5개 복사
→ 네이버 SmartPlace 접속
→ 해당 브랜드 계정으로 로그인
→ 대상 사업장 선택
→ 업체정보의 대표키워드 영역으로 이동
→ 기존 키워드 확인 및 삭제
→ 추천키워드 5개를 하나씩 입력
→ 입력 결과 확인
→ 저장
```

이 과정은 한 매장만 처리할 때는 단순하지만, 여러 매장을 반복 처리하면 시간이 오래 걸리고 실수가 발생하기 쉽다.

## 3. 현재 방식의 문제

### 3.1 반복적인 수작업

매장마다 동일한 화면 이동과 입력을 반복해야 한다. 추천키워드는 이미 데이터로 존재하지만 SmartPlace에 반영하는 마지막 단계만 사람이 다시 입력하고 있다.

### 3.2 매장 선택 오류

운영 계정에는 여러 사업장이 연결될 수 있다. 리포트에서 본 매장과 SmartPlace에서 선택한 사업장이 다르면 다른 매장의 대표키워드를 변경할 위험이 있다.

### 3.3 브랜드 계정 혼동

육수당과 한촌설렁탕은 서로 다른 계정과 로그인 세션을 사용한다. 같은 브라우저 프로필을 공유하거나 잘못된 계정으로 접속하면 사업장 조회와 변경 대상이 섞일 수 있다.

### 3.4 복사·입력 과정의 누락과 오타

키워드 5개를 하나씩 추가하는 동안 다음 오류가 발생할 수 있다.

- 일부 키워드 누락
- 중복 입력
- 다른 매장의 키워드 입력
- 키워드 순서 변경
- 기존 키워드를 잘못 유지하거나 삭제
- 글자 수 또는 SmartPlace 검증 오류를 놓침

### 3.5 변경 결과 추적 부족

누가 어떤 매장의 키워드를 무엇에서 무엇으로 바꿨는지 남지 않으면 이후 성과 분석이나 오류 복구가 어렵다.

## 4. 자동화가 필요한 이유

이 기능의 목적은 단순히 클릭 수를 줄이는 것이 아니다. 이미 분석을 통해 결정된 추천 결과가 실제 운영 화면에 정확히 반영되도록 분석과 실행 사이의 단절을 없애는 것이다.

자동화를 통해 기대하는 효과는 다음과 같다.

- 반복 입력 시간 단축
- 매장과 브랜드를 잘못 선택할 가능성 감소
- 추천된 키워드의 누락·중복·오타 방지
- 적용 전후 값을 기록해 변경 이력 확보
- 매장별 추천과 실제 적용 상태의 일치 여부 확인
- 향후 여러 매장 일괄 적용을 위한 기반 마련

## 5. 최종 사용자 경험

최종적으로 인사이트 리포트의 `#s5`에서 매장별 버튼은 단순한 `5개 복사`가 아니라 SmartPlace 적용 작업의 시작점이 된다.

권장 사용자 흐름은 다음과 같다.

```text
1. 운영자가 리포트에서 대상 매장을 찾는다.
2. 매장명과 추천키워드 5개를 검토한다.
3. `SmartPlace에 등록` 버튼을 누른다.
4. 자동화가 브랜드와 매장을 식별한다.
5. 해당 브랜드의 독립 브라우저 프로필을 연다.
6. 기존 로그인 세션을 확인하고 재사용한다.
7. 세션이 만료된 경우에만 자동 로그인을 수행한다.
8. SmartPlace에서 대상 사업장을 선택한다.
9. 현재 대표키워드와 추천키워드를 비교한다.
10. 변경 예정 내용을 사용자에게 보여준다.
11. 사용자가 승인하면 키워드 5개를 입력한다.
12. 저장 직전 또는 최종 저장 단계에서 다시 확인한다.
13. 적용 결과와 변경 전후 값을 기록한다.
14. 리포트에 성공, 실패 또는 확인 필요 상태를 표시한다.
```

## 6. 버튼 동작의 목표

초기 `5개 복사` 기능은 보조 수단으로 유지할 수 있다. 자동 등록 기능은 별도의 명확한 버튼으로 제공하는 것이 안전하다.

예시:

```text
[5개 복사] [SmartPlace에 등록]
```

`SmartPlace에 등록` 버튼을 눌렀을 때 전달해야 하는 최소 데이터는 다음과 같다.

```json
{
  "brand": "육수당",
  "storeName": "육수당 강남자곡점",
  "storeId": "내부 또는 SmartPlace 사업장 식별자",
  "keywords": [
    "자곡동삼계탕",
    "자곡동냉면",
    "자곡동해장",
    "국밥",
    "콩나물국밥"
  ]
}
```

매장명만으로 자동 선택하면 동명이거나 명칭이 변경된 경우 위험하다. 가능하면 SmartPlace 사업장 ID 또는 별도의 검증된 매장 매핑 테이블을 사용한다.

## 7. 전체 시스템 구성

최종 기능은 다음 네 부분으로 나뉜다.

### 7.1 인사이트 리포트

역할:

- 매장별 추천키워드 5개 표시
- 사용자가 추천 근거와 키워드를 검토할 수 있게 함
- 자동 등록 요청 생성
- 진행 상태와 결과 표시

리포트 HTML은 보안상 직접 Python이나 Playwright를 실행할 수 없다. 따라서 로컬 자동화 서비스와 통신해야 한다.

### 7.2 로컬 자동화 브리지

역할:

- HTML에서 전달한 요청 수신
- 요청 형식과 브랜드·매장·키워드 검증
- 중복 실행 방지
- 로그인 모듈과 SmartPlace 입력 자동화 호출
- 진행 상태와 결과를 HTML에 반환

브리지는 로컬 PC에서만 접근할 수 있도록 제한하고, 임의 웹페이지가 자동화를 호출하지 못하도록 요청 출처와 토큰을 검증해야 한다.

### 7.3 SmartPlace 로그인 모듈

역할:

- 육수당과 한촌설렁탕 계정 설정 관리
- 브랜드별 독립 Chrome 프로필 생성
- `undetected_chromedriver` 기반 브라우저 실행
- 기존 로그인 세션 우선 재사용
- 세션 만료 시 자동 로그인
- CAPTCHA 또는 추가 인증 시 사용자 개입 요청
- 브라우저와 프로필 잠금의 안전한 정리

상세 설계는 다음 handoff 문서를 따른다.

```text
docs/2026-09-01-smartplace-auth-login-handoff.md
```

### 7.4 대표키워드 등록 자동화

역할:

- 올바른 브랜드 계정인지 확인
- 요청된 사업장과 현재 SmartPlace 사업장이 일치하는지 확인
- 업체정보의 대표키워드 영역으로 이동
- 현재 키워드 읽기
- 추천키워드와 차이 계산
- SmartPlace 입력 규칙 사전 검사
- 키워드 삭제·추가
- 저장 전 변경 내용 확인
- 승인된 경우에만 저장
- 성공 여부 재검증

## 8. 데이터 흐름

```text
인사이트 리포트의 DATA.plan.stores

→ 매장 ID와 SmartPlace 사업장 대조
→ 현재 대표키워드 조회
→ 변경 전/후 비교
→ 사용자 승인

→ 저장 결과 재조회
→ 적용 이력 기록
→ 리포트 상태 갱신
```

## 9. 반드시 포함해야 할 안전장치

대표키워드 변경은 외부 서비스의 실제 운영 데이터를 수정하므로 완전 자동 저장보다 확인 가능한 반자동 흐름으로 시작하는 것이 안전하다.

### 9.1 브랜드 검증

- 육수당 요청은 육수당 프로필에서만 처리한다.
- 한촌설렁탕 요청은 한촌설렁탕 프로필에서만 처리한다.
- 로그인된 계정이 예상 브랜드의 사업장을 조회할 수 없는 경우 중단한다.

### 9.2 매장 검증

- 리포트의 매장과 SmartPlace의 현재 사업장이 일치해야 한다.
- 가능하면 매장명 대신 검증된 사업장 ID로 비교한다.
- 매핑이 없거나 둘 이상의 후보가 나오면 자동 선택하지 않는다.

### 9.3 키워드 검증

- 정확히 5개인지 확인한다.
- 빈 값과 중복을 제거하거나 오류로 처리한다.
- SmartPlace의 글자 수 제한을 확인한다.
- 추가 불가능한 키워드, 금칙어 또는 서버 검증 오류를 사용자에게 보여준다.
- 리포트에 표시된 값과 자동화에 전달된 값이 같은지 확인한다.

### 9.4 저장 전 확인

최소한 초기 버전에서는 다음 비교 화면을 보여준 뒤 사용자의 승인을 받는다.

```text
브랜드: 육수당
매장: 강남자곡점

현재 키워드
- 원창동갈비탕
- 인천북항
- 해장
- 갈비탕
- 원창동삼계탕

변경 후 키워드
- 자곡동삼계탕
- 자곡동냉면
- 자곡동해장
- 국밥
- 콩나물국밥

[취소] [입력만 하고 저장하지 않기] [최종 저장]
```

### 9.5 변경 이력

다음 항목을 구조화해 기록한다.

- 실행 일시
- 브랜드
- 매장명과 사업장 ID
- 변경 전 키워드
- 변경 후 키워드
- 실행 모드
- 저장 여부
- 결과 상태
- 실패 단계와 비밀정보를 제외한 오류 요약

## 10. 단계별 구현 목표

### 1단계: 로그인 기반 구축

- 육수당·한촌설렁탕 독립 프로필
- UC 브라우저 실행
- 로그인 세션 재사용
- 만료 시 자동 로그인
- CAPTCHA/추가 인증 감지

### 2단계: 단일 매장 입력 검증

- 리포트에서 한 매장의 데이터 추출
- SmartPlace 대상 매장 확인
- 대표키워드 화면 이동
- 현재 키워드 읽기
- 추천키워드 5개 입력
- 저장하지 않고 화면 상태만 검증

### 3단계: 승인 후 단일 매장 저장

- 변경 전/후 비교
- 사용자 승인
- 최종 저장
- 저장 결과 재조회
- 변경 이력 기록

### 4단계: HTML 버튼 연결

- `SmartPlace에 등록` 버튼 추가
- 로컬 브리지 호출
- 진행 중, 성공, 실패, 확인 필요 상태 표시
- 기존 복사 기능 유지

### 5단계: 다매장 운영 확장

- 처리 큐
- 매장별 독립 결과
- 실패 매장만 재시도
- 중복 실행 방지
- 일괄 실행 전 전체 변경 목록 승인

일괄 자동 저장은 단일 매장 흐름과 감사 로그가 충분히 검증된 뒤 도입한다.

## 11. 사용 상태 정의

리포트에서 각 매장의 적용 상태를 다음처럼 구분할 수 있다.

| 상태 | 의미 |
|---|---|
| 미등록 | 자동화가 실행되지 않음 |
| 확인 필요 | 로그인, 매장 매핑 또는 키워드 검증에 사용자 판단 필요 |
| 입력 완료 | 화면에는 입력했지만 아직 저장하지 않음 |
| 적용 완료 | 저장 후 실제 값이 추천키워드와 일치함 |
| 변경 없음 | 기존 키워드가 이미 추천안과 일치함 |
| 실패 | 브라우저, 로그인, 화면 변경 또는 저장 오류 |

단순히 버튼 클릭이 끝났다는 이유로 `적용 완료`로 표시하면 안 된다. 저장 후 SmartPlace 화면을 다시 읽어 5개 값이 일치할 때만 완료로 본다.

## 12. 성공 기준

최종 기능은 다음 조건을 만족해야 한다.

- 육수당과 한촌설렁탕의 로그인 세션이 서로 섞이지 않는다.
- 유효한 로그인 프로필이 있으면 매번 ID/PW를 입력하지 않는다.
- 리포트에서 선택한 매장과 실제 변경 대상 사업장이 일치한다.
- 리포트의 추천키워드 5개가 누락·중복·오타 없이 전달된다.
- 저장 전에 현재 값과 변경 후 값을 사용자가 확인할 수 있다.
- 사용자 승인 없이는 실제 저장하지 않는다.
- 저장 후 화면을 다시 확인해 실제 반영 여부를 판정한다.
- 실패한 단계와 조치 방법을 알 수 있다.
- 계정정보, 쿠키, 비밀번호가 로그나 결과 파일에 남지 않는다.
- 변경 이력을 통해 언제 어떤 값이 적용됐는지 추적할 수 있다.
- 기존 `5개 복사` 방식도 비상용 수동 절차로 계속 사용할 수 있다.

## 13. 최종적으로 기대하는 운영 모습

운영자는 더 이상 매장마다 키워드를 복사하고 SmartPlace 화면을 반복해서 찾아다니지 않는다. 인사이트 리포트에서 추천 근거를 검토하고 등록 버튼을 누른 뒤, 자동화가 찾아온 정확한 사업장과 변경 내용을 확인하고 승인하는 역할에 집중한다.

자동화는 사람의 판단을 없애는 것이 아니라 다음을 담당한다.

- 정확한 브랜드 세션 선택
- 정확한 사업장 이동
- 반복적인 키워드 입력
- 입력 규칙 검증
- 저장 결과 확인
- 변경 이력 기록

사람은 다음을 담당한다.

- 추천키워드가 사업장에 적합한지 판단
- 매장 매핑이 모호할 때 대상 확인
- CAPTCHA나 추가 인증 처리
- 실제 저장 승인
- 적용 결과와 이후 유입 성과 검토

## 14. 장기적인 확장 방향

로그인과 대표키워드 등록이 안정화되면 다음 기능으로 확장할 수 있다.

- 추천키워드 적용 전후 순위·노출·유입 비교
- 일정 기간 성과가 낮은 키워드의 교체 후보 알림
- 월별 추천안과 실제 SmartPlace 설정의 차이 감지
- 매장별 적용 이력과 성과 대시보드
- 브랜드별 승인자와 실행 권한 분리
- 일괄 적용 예약과 실패 재처리

장기적으로는 `분석 → 추천 → 승인 → 적용 → 성과 검증 → 재추천`이 하나의 폐쇄형 운영 흐름으로 연결되는 것이 목표다.

## 15. 최종 요약

현재 리포트는 어떤 대표키워드를 등록해야 하는지 알려주지만, 실제 SmartPlace 반영은 사람이 반복 수행한다. 최종적으로 완성하려는 기능은 리포트의 매장별 추천키워드와 네이버 SmartPlace를 안전하게 연결해, 브랜드별 로그인 세션과 정확한 매장 검증을 거친 후 사용자의 승인 아래 대표키워드 입력과 저장을 자동화하는 것이다.

이 기능의 핵심 가치는 단순한 입력 속도가 아니라 다음 세 가지다.

1. 분석 결과를 운영에 정확히 반영한다.
2. 잘못된 브랜드·매장·키워드 변경을 예방한다.
3. 적용 결과를 기록하고 이후 성과 검증까지 연결한다.
