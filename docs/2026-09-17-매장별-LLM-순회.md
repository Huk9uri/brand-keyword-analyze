# 매장별 LLM 순회 연결

## 실행 동작

기본 모델은 `gpt-5.6-luna`이며 기존 생성 함수가 `reasoning.effort=none`을 전송한다. 명시적인 `--model`은 시험용으로 유지하고, 과거 환경변수의 모델 값 대신 확정된 기본 모델을 사용한다.

완료된 분석의 results.json에서 추천 자격이 있는 매장을 고유 코드순으로 순회한다. 소고기미역국만 있는 매장, 보류만 있는 매장 등 추천 후보가 없는 매장은 호출하지 않는다. 각 매장의 입력에는 기노출·보류·HMR 제외 정보도 함께 전달한다.

매장별 생성 함수의 입력·프롬프트·스키마·모델 지문을 이용해 동일 실행 폴더의 정상 요약을 재사용한다. 실패한 매장도 기록하고 나머지 매장은 계속 처리한다. 동일 명령 재실행 시 실패 건을 다시 호출한다. 입력이나 프롬프트가 달라진 매장은 새로 생성한다. 새 분석 출력 폴더 사이의 캐시 공유는 이번 범위에 포함하지 않는다.

## 사용 명령

```powershell
.\.venv\Scripts\python.exe -m scripts.menu_keyword_pipeline.delivery_cli --output outputs/menu-keywords-20260917-scheduled
```

매장 코드를 생략하면 전체 대상 순회, `--store-code 000033`을 지정하면 한 매장만 생성한다. 기존 operations 명령도 매장 코드를 전달하지 않으므로 자동으로 순회 경로를 사용한다. 기존 `--prepare-input` 및 `--compare-models`의 진단 기능은 유지한다.

## 저장 및 발송

- `store-summaries/<매장 코드 해시>/`: 매장별 입력·정상 응답·보고서·사용량 영수증
- `store-summary-status.json`: 대상·정상·실패 수, 매장별 결과, 후보 없는 매장 목록. 매장마다 갱신한다.
- `summary.md`: 정상 매장 보고서의 통합본. 일부 실패하면 부분 결과임을 표시한다.

일부 매장 실패 시 반환 코드는 2이며 메일을 보내지 않는다. 재실행해 전체 대상 요약이 정상으로 준비되면 기존 메일 경로로 전달할 수 있다. 기존 메일 중복 방지 정책은 유지한다. 메일 본문 크기·수신함 도착 검증은 별도로 필요하다.

동일 폴더 중복 실행은 `store-summaries.lock`으로 차단한다. 정상 종료와 처리 가능한 예외에서는 잠금을 해제한다. 강제 종료·재부팅으로 남은 잠금은 실행 프로세스가 없는지 확인 후 제거해야 한다. 정상 저장 직전 강제 종료로 API 결과를 잃은 요청은 재호출 비용이 발생할 수 있다.

## 검증 범위

모의 API를 이용해 Luna/none 요청, HMR만 있는 매장 제외, 일부 실패 후 나머지 처리, 재실행 시 성공 매장 캐시 재사용, 부분 결과 메일 차단을 확인했다. 관련 테스트 총 24개 통과. 현재 분석 자료의 대상은 앞서 확인한 131개 매장이며, 이번 구현 검증에서 전량 유료 호출과 실제 메일 발송은 수행하지 않았다.
