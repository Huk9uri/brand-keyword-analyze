# 매장별 추천 프롬프트 구현

매장별 호출(`--store-code`)에 추천 중심 입력·응답 구조를 적용했다. 전체 매장 반복 호출 및 매장별 메일 연결은 이번 변경 범위에 포함하지 않았다.

## 보고서 구조

1. 우선 공략 후보 최대 3개: 판매 메뉴와 수치, 추천 이유, 다른 후보보다 우선할 이유, 확인 사항, 다음 행동
2. 기존 키워드 노출 현황
3. 판매 근거와 데이터 주의사항

핵심 메시지는 실제 판매 근거와 검색 수요가 있으나 유효한 상위 20위 관측에서 미노출이므로 신규 유입 경로로 시험할 가치가 있다는 것이다. 전국 검색량을 지역 방문 수요나 매출 증가로 해석하지 않는다.

## 근거 연결

LLM은 내부 근거 ID와 설명을 반환한다. 코드는 ID의 존재·중복·추천 자격을 검증한 뒤 원자료에서 메뉴명, 매출, 판매수, 검색량, 관측 시점을 삽입한다. 사용자 보고서에는 근거 ID를 표시하지 않는다. 설명에 숫자가 있다는 이유만으로 실패시키지 않는다. 이 검증은 설명의 모든 사실과 판단을 검증하는 장치가 아니다.

## 입력 정리

경쟁 검색 결과와 중복 근거 문장을 제외하고 메뉴를 공통 표로 구성했다. 미연결 메뉴는 사유별 기록 수로 전달하며, 중복 가능성이 있는 금액은 합산하지 않는다. 노출·미노출·보류 키워드, 품질 상태, 관측일은 유지한다.

000110 매장 실제 입력은 JSON 직렬화 기준 17,412자이며 28개 키워드와 추천 자격을 갖춘 12개 조합을 포함한다. 기존 상세 입력은 약 94,067자였다.

## 검증

추천 구조, 부적격 근거 차단, ID 연결과 보고서 출력, 기존 요약·발송 관련 테스트 21개 통과. 최초 실행에서 기존 운영 테스트의 Windows 파일 교체 권한 오류가 발생했으며 새 임시 경로로 재실행 시 통과했다.

실제 데이터로 API 호출 없는 입력 생성까지 확인했다. 이번 프롬프트로 유료 LLM 호출이나 메일 발송은 수행하지 않았으며 모델별 품질 비교는 별도 실행이 필요하다.
