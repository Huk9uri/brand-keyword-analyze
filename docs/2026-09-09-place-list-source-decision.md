# 매장별 지역 경쟁 평가 원천 확정

사용자가 확정한 방향은 매장 좌표 기준 플레이스 목록을 평가의 주 수집 원천으로 사용하는 것이다.
이 결정은 기존 통합검색 기반 수집 방향보다 우선한다.

## 수집 목적별 URL 분리

이번 전환은 **순위·경쟁점 목록 수집에만** 적용한다. 기존 모바일 검색 경로를 완전히 대체하지 않는다.

- 순위·경쟁점 수집: 매장 x·y 좌표를 넣은 `m.place.naver.com/restaurant/list`를 사용한다.
- `keywordList` 수집: **기존 모바일 검색 URL 경로를 유지**한다. 목록 URL로 전환하지 않는다.
- 플레이스 목록에서 확인한 경쟁점의 Place ID를 기존 keywordList 수집기에 전달한다.
  각 수집기의 URL 생성과 브라우저 흐름을 구분하며, 순위 수집의 V4 전환을 keywordList 경로에 일괄 적용하지 않는다.
- 구현 검증에는 순위 URL 변경과 함께 기존 keywordList URL·수집 동작의 회귀 검증을 포함한다.

## 검색 및 평가 기준

- URL: `https://m.place.naver.com/restaurant/list?query={검색어}&x={매장 경도}&y={매장 위도}&level=top&entry=pll`
- 검색어와 좌표는 URL 인코딩을 적용해 구성한다. x는 경도, y는 위도다.
- 매장별로 확인된 Place ID와 좌표를 사용하고, 같은 검색어도 매장별로 따로 수집한다.
- UC·독립 프로필·Selenium으로 렌더링된 플레이스 목록 DOM을 수집한다.
- 좌표는 검색 조건에만 사용한다. 거리 자체는 평가 점수에 포함하지 않는다.
- 측정값의 명칭은 **매장 좌표 기준 플레이스 목록 순위**다. 통합검색 노출 순위와 혼합하지 않는다.
- 새 수집 프로필은 `MOBILE_PLACE_LIST_STORE_LOCATION_ORGANIC20_V4`로 구분한다.
  과거 V2·V3 관측을 새 프로필로 재명명하거나 새 관측 대신 사용하지 않는다.

## 파싱 및 완료 기준

- 일반 매장 카드만 원본 순서대로 추출한다. 배너와 추천 모듈은 순위에서 제외한다.
- 상대경로 상세 링크와 광고 링크의 목적지에서 Place ID를 추출한다.
- 광고 여부와 원본 카드 순서를 보존하며, 광고를 제외해 자연순위를 계산한다.
- 자연순위 20개까지 누락·식별 오류·중복 없이 확보하면 목표 깊이를 충족한다.
- 자연순위 20개 미만이면 실제 목록 종료가 확인된 경우에만 완전한 짧은 목록으로 인정한다.
  끝이 확인되지 않은 목록은 PARTIAL로 보존한다.
- PARTIAL도 관측값과 품질 상태를 함께 DB에 적재할 수 있다. 미노출·경쟁점 0개로 해석하지 않는다.
- 보안 확인 화면은 정상 결과로 처리하지 않으며 사용자 확인이 필요한 상태로 구분한다.

## 현재 구현과 후속 변경

V4 플레이스 목록 경로의 코드 전환과 부천본점 설렁탕 1건의 실제 자동 수집 검증을 완료했다.
기존 통합검색 경로와 keywordList 수집 코드는 유지한다. 최신 평가 실수집은 V4 입력을 요구한다.

목록 URL 구성, 목록 전용 카드 파싱·스크롤·완료 판정 및
V4 프로필의 원천 재수출·평가 선택을 함께 변경했다.
첨부 HTML의 일반 매장 카드 106개(광고 6개·자연 100개)를 실제 파서로 검증했다.
부천본점 실제 검증은 자연순위 20개·광고 2개로 SUCCESS이며 로컬 저장만 수행했다.
전체 25건 실수집과 신규 DB 적재는 후속 실행 사항이다.
