# 키워드 발굴 프로젝트 테이블 정의서

- 작성 기준일: 2026-09-18
- 작성 기준: 저장소의 SQL DDL, Python 조회·저장 코드 및 Git 추가 이력
- 대상 시스템: SQL Server(`SKYPOS`, `SEIERP_IYN_BAK`, `naverDB`) 및 로컬 SQLite

## 1. 문서 목적과 범위

이 문서는 다음 두 가지를 정리한다.

1. 키워드 발굴·검증·추천 과정에서 실제로 조회하는 기존 테이블과 뷰
2. 이 프로젝트에서 새로 정의한 SQL Server 테이블 12개와 로컬 SQLite 테이블 4개

여기서 **키워드 발굴**은 최근 판매 메뉴와 리뷰에서 후보를 만들고, 검색량과 네이버 플레이스 노출 순위를 확인한 뒤, 매장별 추천 후보를 만드는 전체 흐름을 뜻한다.

> 주의: 본 정의서는 저장소 기준의 논리·물리 정의서다. 운영 DB에 DDL이 실제 반영되었는지와 운영 DB의 기존 원천 테이블 전체 스키마는 별도 권한으로 확인해야 한다. 프로젝트의 DDL은 애플리케이션이 자동 실행하지 않는다.

## 2. 데이터 흐름과 사용 테이블

| 단계 | 목적 | 사용 테이블·뷰 | 구분 |
|---|---|---|---|
| 매장 모집단 | 운영 중인 한촌 매장과 네이버 플레이스 ID 확인 | `SEIERP_IYN_BAK.dbo.FROP_STORE`, `dbo.vw_naver_store_hours_targets`, `dbo.naver_place_location` | 기존 2개 + 신규 1개 |
| 판매 메뉴 발굴 | 최근 30일 매장별 판매 메뉴·매출·수량 조회 | `SKYPOS.dbo.prep_매출뷰` | 기존 |
| 메뉴명 연결 | POS 메뉴 코드를 ERP 메뉴명으로 변환 | `SEIERP_IYN_BAK.dbo.FRMI_MENULINKCODE`, `SEIERP_IYN_BAK.dbo.BSIT_ITEM` | 기존 |
| 리뷰 후보 발굴 | 최근 12개월 블로그·방문자 리뷰에서 표현 추출 | `dbo.naver_review_blog`, `dbo.naver_review_visitor` | 기존 |
| 후보 저장 | 매장/브랜드 후보와 리뷰 근거 저장 | `dbo.naver_keyword_discovery_candidate`, `dbo.naver_keyword_discovery_review_term` | 신규 |
| 검색량 관측 | 네이버 검색광고 검색량 원문과 파싱 결과 저장·재사용 | `dbo.naver_keyword_search_volume_snapshot` | 신규 |
| 순위 관측 | 키워드별 네이버 장소 결과와 대상 매장 노출 순위 저장 | `dbo.naver_keyword_discovery_snapshot`, `dbo.naver_keyword_discovery_result` | 신규 |
| 대표키워드 관측 | 플레이스 상세의 대표키워드 목록과 변경 상태 저장 | `dbo.naver_place_keyword_snapshot`, `dbo.naver_place_keyword_result` | 신규·보조 흐름 |
| 후보 평가 | 후보별 판정, 근거, 수동 검토 결과 저장 | `dbo.naver_keyword_evaluation_run`, `dbo.naver_keyword_evaluation_result`, `dbo.naver_keyword_evaluation_evidence`, `dbo.naver_keyword_evaluation_review` | 신규 |
| LLM 요약 | 매장별 추천과 종합 요약, 실행 이벤트 저장 | SQLite `runs`, `summaries`, `events`, `overviews` | 신규·로컬 |

현재 메뉴 기반 일일 추천의 핵심 입력은 `prep_매출뷰`, `FROP_STORE`, `FRMI_MENULINKCODE`, `BSIT_ITEM`, `vw_naver_store_hours_targets`이며, 검색량과 순위는 신규 스냅샷 테이블에서 재사용한다. 리뷰 기반 후보 테이블과 평가 테이블은 별도 후보 발굴·평가 흐름에서 사용한다.

## 3. 기존 원천 테이블·뷰

기존 원천은 이 프로젝트가 생성하지 않았으므로, 아래에는 프로젝트가 실제 사용하는 컬럼만 기록한다.

### 3.1 `SKYPOS.dbo.prep_매출뷰`

- 용도: 최근 30일 매장×메뉴 매출·판매수량과 매장×일자 집계 조회
- 필터: `BRD_CD='HC1001'`, `gubun='01'`, 조회 시작일 이상·종료일 미만
- 사용 컬럼: `STR_NO`, `CMDT_CD`, `SDA_DT`, `SC_AMT_TTL`, `SC_QTY`, `BRD_CD`, `gubun`
- 산출값: POS 매장코드, 메뉴코드, 판매일, 매출액 합계, 판매수량 합계

### 3.2 `SKYPOS.dbo.T_POS_SALE_CMDT`

- 용도: 브랜드 POS 자료의 최종 판매일 확인
- 사용 컬럼: `SDA_DT`, `BRD_CD`, `gubun`
- 비고: 현재 일일 메뉴 파이프라인의 판매 집계 자체는 `prep_매출뷰`를 사용한다.

### 3.3 `SEIERP_IYN_BAK.dbo.FROP_STORE`

- 용도: ERP 매장 모집단과 POS 매장코드 연결, 개·폐점 정보 확인
- 사용 컬럼: `CD_STORE`, `NM_STORE`, `NO_POSCONNCODE`, `DT_OPEN`, `DT_CLOSE`, `CD_CORP`, `CD_BRAND`, `CD_TYPE1`, `CD_OPERATION`
- 주요 필터: 법인 `01`, 브랜드 `001`; 전체 운영 매장 모집단에서는 매장유형 `001`, 운영상태 `002`, 폐점일 공백 조건을 추가한다.

### 3.4 `SEIERP_IYN_BAK.dbo.FRMI_MENULINKCODE`

- 용도: POS 메뉴코드(`CD_STMENU`)를 시스템 품목코드(`CD_SYSITEM`)에 연결
- 사용 컬럼: `CD_CORP`, `CD_STMENU`, `CD_SYSITEM`

### 3.5 `SEIERP_IYN_BAK.dbo.BSIT_ITEM`

- 용도: 시스템 품목코드의 메뉴명 조회
- 사용 컬럼: `CD_CORP`, `CD_SYSITEM`, `NM_ITEM`

### 3.6 `naverDB.dbo.vw_naver_store_hours_targets`

- 유형: 기존 뷰
- 용도: ERP 매장과 네이버 매장·플레이스 ID의 연결 상태 확인
- 사용 컬럼: `BRAND_CODE`, `STORE_CODE`, `NAVER_STORE_NAME`, `NAVER_PLACE_ID`, `PLACE_ID_STATUS`
- 정상 판정: 한 매장에 일관된 한 건이 있고 `PLACE_ID_STATUS='CONSISTENT'`인 경우

### 3.7 `naverDB.dbo.naver_review_blog`

- 용도: 최근 12개월 블로그 리뷰 원문에서 후보 표현 추출
- 사용 컬럼: `review_blog_id`, `brand_type`, `place_id`, `place_name`, `date`, `context`, `title`
- 연결: 추출 근거의 `source_type='BLOG'`, `source_review_id=review_blog_id`

### 3.8 `naverDB.dbo.naver_review_visitor`

- 용도: 최근 12개월 방문자 리뷰 원문·키워드에서 후보 표현 추출
- 사용 컬럼: `review_visitor_id`, `brand_type`, `place_id`, `place_name`, `date`, `context`, `keyword`
- 연결: 추출 근거의 `source_type='VISITOR'`, `source_review_id=review_visitor_id`

## 5. 프로젝트 신규 SQL Server 테이블 상세 정의

### 5.1 `dbo.naver_keyword_discovery_candidate`

- 목적: 리뷰·메뉴·운영 키워드·검색광고 연관어를 통합한 매장 또는 브랜드 후보 저장
- 기본키: `candidate_id`
- 업무 유일키: `(run_id, brand_code, candidate_scope, place_id, normalized_keyword)`

| 컬럼 | 형식 | NULL | 설명 |
|---|---|---:|---|
| `candidate_id` | `bigint IDENTITY` | N | 후보 식별자 |
| `run_id` | `uniqueidentifier` | N | 후보 발굴 실행 ID |
| `brand_code` | `varchar(10)` | N | 브랜드 코드 |
| `candidate_scope` | `varchar(10)` | N | `STORE` 또는 `BRAND` |
| `place_id` | `varchar(50)` | N | 매장 후보의 플레이스 ID. 브랜드 후보는 빈 문자열 |
| `normalized_keyword` | `nvarchar(255)` | N | 정규화된 후보 키워드 |
| `term_category` | `varchar(30)` | N | 후보 분류 |
| `store_review_count` | `int` | N | 해당 매장 리뷰 언급 수 |
| `brand_review_count` | `int` | N | 브랜드 전체 리뷰 언급 수 |
| `brand_store_count` | `int` | N | 언급이 확인된 브랜드 매장 수 |
| `weighted_mention_score` | `decimal(12,3)` | N | 시간 가중 언급 점수 |
| `from_menu` | `bit` | N | 매장 메뉴 출처 여부 |
| `from_brand_menu` | `bit` | N | 브랜드 대표메뉴 출처 여부 |
| `from_operation_keyword` | `bit` | N | 운영팀 제공 출처 여부 |
| `from_searchad_related` | `bit` | N | 검색광고 연관어 출처 여부 |
| `from_review` | `bit` | N | 리뷰 출처 여부 |
| `candidate_status` | `varchar(30)` | N | `READY`, `INSUFFICIENT_EVIDENCE`, `REVIEW_REQUIRED`, `EXCLUDED` |
| `generated_at` | `datetime2(0)` | N | 후보 생성 시각 |

- 제약: 매장 후보는 `place_id` 필수, 브랜드 후보는 빈 문자열이어야 하며 각 집계값은 0 이상이다.
- 인덱스: `(place_id, candidate_status, generated_at)`

### 5.2 `dbo.naver_keyword_discovery_review_term`

- 목적: 후보가 어떤 리뷰의 어떤 표현에서 추출되었는지 추적
- 기본키: `review_term_id`
- 외래키: `candidate_id` → `naver_keyword_discovery_candidate.candidate_id`
- 업무 유일키: `(run_id, source_type, source_review_id, normalized_keyword)`

| 컬럼 | 형식 | NULL | 설명 |
|---|---|---:|---|
| `review_term_id` | `bigint IDENTITY` | N | 리뷰 근거 식별자 |
| `candidate_id` | `bigint` | N | 연결 후보 ID |
| `run_id` | `uniqueidentifier` | N | 후보 발굴 실행 ID |
| `source_type` | `varchar(10)` | N | `BLOG` 또는 `VISITOR` |
| `source_review_id` | `bigint` | N | 원본 리뷰 ID |
| `brand_code` | `varchar(10)` | N | 브랜드 코드 |
| `place_id` | `varchar(50)` | N | 플레이스 ID |
| `review_date` | `date` | N | 리뷰 작성일 |
| `raw_expression` | `nvarchar(500)` | N | 원문에서 뽑은 표현 |
| `normalized_keyword` | `nvarchar(255)` | N | 정규화 키워드 |
| `term_category` | `varchar(30)` | N | 표현 분류 |
| `time_weight` | `decimal(3,2)` | N | 시간 가중치: `0.50`, `0.80`, `1.00` |
| `extraction_method` | `varchar(20)` | N | `RULE`, `DICTIONARY`, `LLM` |
| `review_required` | `bit` | N | 사람 검토 필요 여부 |
| `evidence_excerpt` | `nvarchar(1000)` | N | 근거 문맥 발췌 |
| `analyzed_at` | `datetime2(0)` | N | 분석 시각 |

- 인덱스: `(place_id, normalized_keyword, review_date)`

### 5.3 `dbo.naver_keyword_discovery_snapshot`

- 목적: 키워드·대상 매장·검색 위치별 네이버 장소 검색 1회의 요청과 수집 상태 저장
- 기본키: `snapshot_id`
- 업무 유일키: `(run_id, task_key)`

| 컬럼 | 형식 | NULL | 설명 |
|---|---|---:|---|
| `snapshot_id` | `bigint IDENTITY` | N | 순위 관측 식별자 |
| `run_id` | `uniqueidentifier` | N | 수집 실행 ID |
| `task_key` | `char(64)` | N | 검색 작업 중복 방지 해시 |
| `query` | `nvarchar(255)` | N | 요청 검색어 |
| `normalized_query` | `nvarchar(255)` | N | 정규화 검색어 |
| `target_store_id` | `nvarchar(100)` | N | 대상 매장의 내부 식별자 |
| `target_store_name` | `nvarchar(200)` | N | 대상 매장명 |
| `location_name` | `nvarchar(200)` | N | 검색 위치 이름 |
| `latitude` | `decimal(10,7)` | Y | 검색 위도 |
| `longitude` | `decimal(10,7)` | Y | 검색 경도 |
| `device_type` | `varchar(10)` | N | `MOBILE` 또는 `PC` |
| `source_type` | `varchar(20)` | N | `EXCEL` 또는 `DATABASE` |
| `source_id` | `nvarchar(100)` | N | 입력 원천 식별자 |
| `requested_result_limit` | `smallint` | N | 요청 결과 수 |
| `observed_result_count` | `smallint` | N | 실제 관측 결과 수 |
| `result_end_reached` | `bit` | N | 결과 끝 도달 여부 |
| `collect_status` | `varchar(30)` | N | 수집 상태 |
| `collect_msg` | `nvarchar(1000)` | Y | 오류·상태 설명 |
| `parser_version` | `varchar(30)` | N | 파서 버전 |
| `final_url` | `nvarchar(2000)` | N | 최종 접근 URL |
| `collected_at` | `datetime2(0)` | N | 수집 시각 |

- 제약: 위도 `-90~90`, 경도 `-180~180`, 관측 수 0 이상
- 주요 인덱스: `(query, collected_at)`, `(target_store_id, collected_at)`, `(collect_status, collected_at)`, `(run_id)`

### 5.4 `dbo.naver_keyword_discovery_result`

- 목적: 한 검색 스냅샷에서 관측한 광고·자연 장소 결과와 대상 매장 매칭 저장
- 기본키: `(snapshot_id, raw_position)`
- 외래키: `snapshot_id` → `naver_keyword_discovery_snapshot.snapshot_id`

| 컬럼 | 형식 | NULL | 설명 |
|---|---|---:|---|
| `snapshot_id` | `bigint` | N | 순위 관측 ID |
| `raw_position` | `smallint` | N | 화면 원시 노출 순서 |
| `organic_rank` | `smallint` | Y | 광고 제외 자연 순위 |
| `place_id` | `varchar(50)` | N | 결과 플레이스 ID |
| `place_name` | `nvarchar(300)` | N | 결과 매장명 |
| `category` | `nvarchar(300)` | Y | 카테고리 |
| `is_ad` | `bit` | N | 광고 결과 여부 |
| `detail_url` | `nvarchar(2000)` | N | 상세 URL |
| `distance_text` | `nvarchar(100)` | Y | 화면의 거리 문자열 |
| `is_own_store` | `bit` | N | 자사 매장 여부 |
| `matched_store_id` | `nvarchar(100)` | Y | 매칭된 내부 매장 ID |
| `match_method` | `varchar(30)` | N | 매칭 방법 |
| `is_target_store` | `bit` | N | 현재 검색 과제의 대상 매장 여부 |

- 제약: 원시 순서와 자연 순위는 1 이상이다.
- 유일 인덱스: 같은 스냅샷에서 NULL이 아닌 `organic_rank`는 유일

## 8. 운영상 해석 주의사항

- 검색량 `total_count`는 전국 검색광고 관측값이며 지역 수요나 매출 전환율과 동일하지 않다.
- 순위 미노출은 `collect_status`, 실제 관측 수, 결과 끝 도달 여부가 정상일 때만 판단해야 한다.
- `FAILED`, `INVALID`, 차단, 타임아웃을 검색량 0 또는 미노출로 바꾸면 안 된다.
- `is_own_store`는 자사 전체 여부이고 `is_target_store`는 해당 검색 과제의 목표 매장 여부다.
- 리뷰 추출 결과는 판매 사실의 증명이 아니며, `review_required`와 평가 근거를 함께 봐야 한다.
- SQLite는 중앙 운영 DB가 아니라 로컬 결과 저장소다. 백업·보존·동시 접근 정책이 별도로 필요하다.
