## 3. 업무 범위와 운영 흐름

1. **업무가 시작되는 조건:** 매일 오전 9시(한국 시간) Codex 정기 자동화 또는 담당자의 수동 실행. 실행 PC·런타임·네트워크·DB 접근이 가능해야 한다.
2. **처리 순서:**
   - 실행일 당일을 제외한 직전 30일 POS 실적을 조회한다. 9월 18일 실행이면 8월 19일~9월 17일이다.
   - ERP 매장·메뉴 코드를 연결하고 기존 메뉴→키워드 목록으로 매장별 매출·판매량을 합산한다.
   - 판매가 확인된 키워드를 중복 제거하고 유효한 검색량은 재사용하며 필요한 자료만 수집한다.
   - 매장×키워드 순위 조사 목록을 생성하고 필요한 순위를 수집한다. 요청 간격은 15초를 유지한다.
   - 판매 확인·검색량 양수·정상 관측·상위 20개 미노출 조건으로 후보를 판정한다.
   - 매장별 LLM이 최대 5개 후보와 이유를 작성한다. 코드가 자격·개수·근거 연결을 검사한다.
   - 매장별 결과를 DB에 저장하고 코드 집계와 종합 요약을 생성한다.
   - 검증 완료 요약을 Gmail API로 발송하고 발송 결과를 기록한다.
3. **결과 확인 방법:** 실행 상태 JSON, `summary.md`, `mail-preview.html`, `store-reports.md`, `mail-delivery.json`과 실제 수신함을 확인한다.
4. **정기적으로 해야 하는 일:** 오전 실행 결과 점검, 실패 처리, 메뉴 연결 목록·제외 목록 검토, API 비용·인증 상태 점검, 기록 백업.
5. **예외 상황 대응:** 수집 실패를 검색량 0이나 미노출로 처리하지 않는다. POS 공백을 매출 하락으로 단정하지 않는다. 발송 상태가 UNKNOWN/SENDING이면 수신·발송 이력을 확인하기 전 재전송하지 않는다.

## 4. 시스템·작업 환경

- **사용 도구·서비스:** Windows, Python `.venv`, SQL Server, 브라우저 기반 네이버 순위 수집, 네이버 검색광고 검색량 API, OpenAI API, SQLite, Gmail API, Codex 정기 자동화.
- **저장소·폴더 위치:** `C:\workspace\brand_analyze`. 원격 저장소 주소·배포 브랜치·정식 릴리스 버전은 별도 확인 필요.
- **운영 화면·대시보드:** 현재 파일 기반 결과와 Codex 실행 화면을 사용. 전용 관리자 화면의 운영 완료는 확인되지 않음.
- **배포·실행 방법:** 프로젝트 폴더에서 아래 명령 실행. 최초 환경 구성 시 기본 프로젝트 의존성과 `requirements-gmail.txt`를 설치한다.

```powershell
.venv/Scripts/python.exe -m scripts.menu_keyword_pipeline.operations --scheduled --send-mail --allow-write --allow-network
```

- 위 명령은 실제 수집·유료 LLM 호출·메일 발송을 수행할 수 있다. 단순 상태 확인에는 실행하지 않는다.
- 발송 없이 분석 단계만 실행할 경우:

```powershell
.venv/Scripts/python.exe -m scripts.menu_keyword_pipeline.cli --collect --allow-write --allow-network
```

- 출력 경로는 자동 생성한다. 이미 존재하는 출력 경로를 CLI에 다시 지정하면 거부한다. 정상 수집 자료는 DB에서 재사용한다.
- **로그 확인 위치:** `outputs/scheduled-menu-keywords/operations.json`, 해당 실행 폴더의 `status.json`, `delivery-status.json`, `store-summary-status.json`, `overview-receipt.json`, `mail-delivery.json`.
- **권한 요청 담당자·절차:** 담당자 실명·연락처는 미확정. 인계자가 사내 DB, OpenAI 프로젝트, Google Cloud 프로젝트의 관리자를 확인하고 회사 절차에 따라 접근을 요청해야 한다.

> 🔐 비밀번호·API 키·개인 이메일·토큰은 이 문서에 기록하지 않는다. 현재 설정은 프로젝트 `.env`, OAuth 파일은 `.secrets/`에 보관하며 비밀 파일을 버전 관리에 포함하지 않는다. 회사 승인 비밀정보 보관소와 접근 승인 절차는 별도 확정 필요. 로컬 보관 위치를 회사 승인 보관소로 간주하지 않는다.

## 5. 주요 기능·구조

- **핵심 기능:** POS 기반 후보 발굴, 검색량·순위 수집과 재사용, 매장별 추천 요약, 코드 집계, 종합 보고서, Gmail 발송, 중복 실행·발송 방지.
- **데이터 입력:**
  - POS 원본: `SKYPOS.dbo.prep_매출뷰`.
  - 매장 연결: `SEIERP_IYN_BAK.dbo.FROP_STORE`.
  - 메뉴 연결: `SEIERP_IYN_BAK.dbo.FRMI_MENULINKCODE`, `BSIT_ITEM`.
  - 메뉴→키워드 규칙: `inputs/hanchon_menu_keywords.json`.
  - 외부 검색량: `dbo.naver_keyword_search_volume_snapshot`.
  - 외부 순위: `dbo.naver_keyword_discovery_snapshot`, `dbo.naver_keyword_discovery_result`.
  - 외부 수집 테이블의 연결 DB명은 실제 운영 연결 설정에서 확인한다.
- **처리 로직:**
  - `repository.py`: POS·ERP 조회와 외부 수집 어댑터.
  - `workflow.py`, `cli.py`: 수집·분석 실행과 출력 관리.
  - `recommendation.py`: 추천 자격 판정, 프롬프트, 응답 검사.
  - `store_summaries.py`, `summary_db.py`: 매장별 호출과 로컬 DB 저장.
  - `overview.py`: 코드 집계·종합 요약 생성.
  - `gmail_sender.py`, `gmail_auth.py`: HTML/텍스트 메일과 OAuth 인증.
  - `operations.py`: 전체 실행 및 보고 단계 재시도 연결.
- **코드와 LLM의 구분:** 코드는 추천 자격·수집 상태·근거 연결을 검사한다. LLM은 후보 중 최대 5개를 선택하고 순서·이유를 작성한다. 검색량 내림차순을 프롬프트로 지시하지만 현재 코드 검증은 그 순서까지 강제하지 않는다. 전체 요약은 검색량과 추천 매장 수를 함께 해석한다.
- **결과물·출력:** 실행별 JSON, `summary.md`, `store-reports.md`, `mail-preview.html`, `mail-preview.eml`, 로컬 `outputs/llm-results.sqlite3`. 원본·수집·LLM 결과가 단일 중앙 DB에 통합된 구조는 아니다.
- **외부 연동:** 네이버 검색량·순위 수집, OpenAI 요약, Gmail API 발송. Gmail은 발송 전용 권한을 사용한다.
- **주의할 의존성:** DB 접근, 브라우저·수집 대상 화면 변화, API 한도·크레딧, OAuth 갱신, 정기 자동화 실행 환경. 전국 검색량을 지역 수요나 전환율로 해석하지 않는다.
