# Gmail API 정기 요약 발송

매일 오전 9시(한국 시간)의 기존 정기 실행을 수집·분석 → Luna/none 매장별 요약 → DB 집계 → 종합 요약 → Gmail API 발송으로 연결했다. 메일 본문은 종합 요약이며 이번 경로에서는 상세 자료를 첨부하지 않는다. 발신·수신은 테스트용 `huk9uri@gmail.com`이다. 기존 SMTP 경로는 기본 실행에서 사용하지 않는다.

## 최초 인증 — 사용자 Google 계정 권한 허용 필요

1. Google Cloud 프로젝트에서 Gmail API를 사용 설정한다.
2. Google Auth Platform에서 동의 화면을 구성하고, 테스트 상태라면 발신 계정 `huk9uri@gmail.com`을 테스트 사용자로 등록한다.
3. OAuth 클라이언트를 **데스크톱 앱** 유형으로 만들고 내려받은 JSON을 `C:/workspace/brand_analyze/.secrets/gmail-client.json`에 저장한다.
4. 프로젝트 폴더에서 다음 명령을 실행하고 브라우저에서 `huk9uri@gmail.com`으로 로그인해 메일 발송 권한을 허용한다.

```powershell
.\.venv\Scripts\python.exe -m scripts.menu_keyword_pipeline.gmail_auth
```

토큰은 `.secrets/gmail-token.json`에 저장하며 `.secrets/`는 Git에서 제외한다. 비밀번호·클라이언트 비밀값·토큰을 채팅에 보내지 않는다. 앱 비밀번호가 아니라 OAuth 인증이며 요청 범위는 `https://www.googleapis.com/auth/gmail.send`다. 공식 안내: [Gmail 메시지 발송](https://developers.google.com/workspace/gmail/api/guides/sending), [데스크톱 앱 OAuth](https://developers.google.com/identity/protocols/oauth2/native-app).

## 실행

```powershell
.\.venv\Scripts\python.exe -m scripts.menu_keyword_pipeline.operations --scheduled --send-mail --allow-write --allow-network
```

동일 날짜에 정상 완료한 실행은 반복하지 않는다. 메일 단계가 미완료면 저장된 분석 폴더를 재사용한다. 매장 요약 또는 종합 요약이 미완료면 발송하지 않는다. 실행 환경의 컴퓨터와 Codex 정기 실행 환경이 동작해야 한다.

기존 완료 보고서 발송을 별도로 시험하려면 다음 명령을 사용한다. 같은 입력의 정상 요약은 캐시로 재사용한다.

```powershell
.\.venv\Scripts\python.exe -m scripts.menu_keyword_pipeline.delivery_cli --output outputs/menu-keywords-20260917-scheduled --send-mail
```

## 실패와 중복

인증 실패는 발송 전 오류이므로 인증 보완 후 재시도 가능하다. 명시적인 API 거절은 REJECTED로 기록한다. 타임아웃이나 서버 오류로 발송 여부가 불확실하면 UNKNOWN으로 기록하고 자동 재발송하지 않는다. SENDING도 동일하게 확인이 필요하다. 동일 내용의 ACCEPTED는 다시 보내지 않는다. 발송 중에는 폴더 잠금을 사용하며, 확인 전 잠금이나 발송 기록을 삭제하면 중복 발송 위험이 있다.

Gmail API 수락 시 메시지 ID를 mail-delivery.json에 보존한다. API 수락은 수신함 도착을 의미하지 않으므로 테스트 메일 도착은 별도 확인한다. 현재 최초 OAuth 클라이언트·토큰이 없어 실제 발송은 아직 검증하지 못했다.
