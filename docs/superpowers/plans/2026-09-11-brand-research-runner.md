# 브랜드 키워드 반복 조사 1차 구현 계획

실행 방식: executing-plans 절차로 현재 작업에서 순차 구현한다. 사용자가 승인한 1차 범위는 검토 후보를 입력받아 매출·검색량·순위를 연결한 보고서를 만드는 것이다.

## 목표와 설계

검토된 후보 JSON과 기간을 입력받는 CLI를 추가한다. 후보 자동 생성·최종 추천·등록·유입 효과 검증은 제외한다. 기존 UC 순위 수집기와 검색광고 수집기를 재사용하고, 기존 평가 점수 계약에 SKYPOS를 섞지 않는다.

- `scripts/brand_keyword_research/core.py`: 설정 검증, 기간, 관측 판정 및 한글 보고서.
- `scripts/brand_keyword_research/repository.py`: 매출·검색량·순위 읽기 전용 조회. 매출 조인 합계 검증, 메뉴 모호성 표시.
- `scripts/brand_keyword_research/cli.py`: 조회·선택 수집·재조회·동결 출력. 실행별 새 출력 경로, 예외 시 비밀정보 없는 실패 기록.
- `inputs/brand_keyword_research.hanchon.json`: 승인된 브랜드·대표 매장 좌표·검토 후보·검색량 기간 정의. 과거 출력 폴더에 의존하지 않는 설정.
- `tests/test_brand_keyword_research.py`: 중복 입력, 날짜, 매출 미확인, 부분 순위, 광고, 최신 실패, 재사용, 오프라인 재현·예외 상태 검증.

조회 시 매출 최신 날짜를 먼저 확인하고 기본 기간은 최신 완료월로 정하되 자료가 오래됐으면 경고한다. 명시 기간은 시작 포함·종료 미포함이다. 금액은 SC_AMT_TTL로 명명하며 회계 확정 매출이라고 부르지 않는다. 한촌만 우선 지원한다.

검색량·순위는 유효기간 내 최신 자료를 재사용한다. 위치·프로필·시간이 일치하지 않으면 재사용하지 않는다. 조회 모드는 수집하지 않고 부족 상태를 보고한다. 수집은 명시 플래그가 있을 때만 실행하며 중단 상태를 실패 없는 완료로 처리하지 않는다. 저장 후 DB를 다시 읽어 보고한다.

실행 결과: 설정, 원자료 JSON, 요약 JSON, 한글 Markdown, 상태 JSON. 오프라인 입력으로 동일 결과를 재생할 수 있다. 후보가 근거 부족·조건부여도 자료를 숨기지 않고 진단으로 구분한다.
