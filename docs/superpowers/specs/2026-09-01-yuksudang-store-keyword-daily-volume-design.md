# 육수당 매장별 키워드 최근 30일 일간 검색량 추정 모델 설계

## 1. 목적

`육수당_매장별 대표키워드 적용 5가지 산출 (1).xlsx`의 `육수당 키워드검색량0513` 시트에 있는 매장별 `키워드1`, `키워드2`, `키워드3`을 대상으로 최근 30일의 일간 검색량 추정치를 계산한다.

이 모델은 실제 일별 검색 로그를 수집하지 않는다. 네이버 검색광고 API의 최근 30일 PC·모바일 검색량을 절대 기준으로 사용하고, 네이버 DataLab API의 일별 상대 검색 비율을 날짜별 가중치로 사용한다.

## 2. 범위

### 포함

- 원본 엑셀에서 매장명과 키워드1·2·3 추출
- 네이버 검색광고 API를 통한 키워드별 PC·모바일 검색량 조회
- 네이버 DataLab API를 통한 최근 30일 일별 ratio 조회
- 앵커 없이 키워드별 독립 정규화
- 키워드별 오류 격리, 재시도 및 캐시
- 계산 결과 JSON/CSV 생성
- 원본 엑셀을 보존한 새 결과 엑셀 생성
- 요약 시트와 일간 상세 시트 추가
- 자동 테스트와 결과 검증

### 제외

- 네이버 플레이스 순위 및 경쟁점 `keywordList` 수집
- 대표키워드 추천 또는 교체
- DB 저장
- 장기 시계열 보존
- 스케줄러 등록
- 원본 엑셀 덮어쓰기

```text

```

비밀값은 로그, JSON, CSV, 엑셀, 테스트 출력에 포함하지 않는다.

## 4. 아키텍처

핵심 수집·계산은 Python으로 구현하고 엑셀 입출력과 시각 검증은 Node.js의 `@oai/artifact-tool`로 처리한다.

```text
원본 XLSX
  → Node.js 입력 추출
  → 정규화된 입력 JSON
  → Python API 수집·계산
  → 결과 JSON/CSV
  → Node.js 결과 XLSX 생성
  → 값·수식·레이아웃 검증
```

### Python 책임

- `.env` 로드와 필수 설정 검증
- 검색광고 API 서명 및 요청
- DataLab API 요청
- 키워드 정규화와 중복 제거
- 재시도, 캐시, 오류 분류
- 일간 추정량 계산
- 기계 판독 가능한 결과 생성

### Node.js 책임

- 원본 XLSX 읽기
- 매장명과 키워드1·2·3 추출
- 원본 서식을 유지한 결과 XLSX 생성
- 결과 시트 추가
- 주요 범위 검사 및 렌더링 검증

Python 모델은 엑셀에 종속되지 않도록 JSON 입력과 JSON 출력을 공개 인터페이스로 사용한다.

## 5. API 수집

### 검색광고 API

- 키워드별 PC 검색량과 모바일 검색량을 조회한다.
- 동일 키워드는 한 번만 조회하고 모든 매장에서 결과를 재사용한다.
- API의 저검색량 표기값은 원문과 파싱 상태를 함께 기록한다.
- 검색량을 숫자로 확정할 수 없는 값은 임의의 숫자로 치환하지 않는다.

### DataLab API

- 조회 종료일은 기본적으로 실행일로 한다.
- 시작일은 종료일에서 29일을 뺀 날짜로 한다.
- 한 매장의 유효한 키워드1·2·3을 하나의 요청에 담는다.
- 앵커 키워드는 포함하지 않는다.
- 키워드가 비어 있거나 중복되면 유효한 고유 키워드만 요청한다.

## 6. 계산

키워드 `k`, 날짜 `d`에 대해 다음 값을 정의한다.

```text
M_pc(k)     = 검색광고 API의 최근 30일 PC 검색량
M_mobile(k) = 검색광고 API의 최근 30일 모바일 검색량
M_total(k)  = M_pc(k) + M_mobile(k)
R(k,d)      = DataLab의 날짜별 ratio
S(k)        = 최근 30일 R(k,d)의 합
```

일간 추정치는 다음과 같다.

```text
E_total(k,d)  = M_total(k)  × R(k,d) ÷ S(k)
E_pc(k,d)     = M_pc(k)     × R(k,d) ÷ S(k)
E_mobile(k,d) = M_mobile(k) × R(k,d) ÷ S(k)
```

DataLab의 요청별 정규화 배율은 분자와 분모에서 상쇄되므로 앵커 없이 계산할 수 있다.

### 정수 배분

단순히 날짜별 값을 각각 반올림하면 30일 합계가 월간 검색량과 달라질 수 있다. 최종 정수값은 최대 나머지 방식으로 배분한다.

1. 날짜별 실수 추정치를 계산한다.
2. 각 값을 내림한다.
3. 월간 검색량과 내림값 합계의 차이를 계산한다.
4. 소수점 나머지가 큰 날짜부터 1씩 배분한다.

이를 통해 다음 불변조건을 유지한다.

```text
Σ E_total(k,d)  = M_total(k)
Σ E_pc(k,d)     = M_pc(k)
Σ E_mobile(k,d) = M_mobile(k)
```

전체 일간 추정량은 PC 일간 추정량과 모바일 일간 추정량의 합으로 저장한다.

## 7. 상태와 예외 처리

| 상태 | 의미 |
|---|---|
| `success` | 검색량과 ratio를 정상 계산 |
| `missing_keyword` | 원본 키워드가 비어 있음 |
| `searchad_no_data` | 검색광고 API에서 유효 검색량을 얻지 못함 |
| `datalab_no_data` | DataLab series가 없거나 30일 ratio 합이 0 |
| `partial_api_error` | 한 API만 실패해 계산 불가 |
| `invalid_input` | 키워드 또는 매장 입력 형식 오류 |

한 키워드의 실패가 다른 매장이나 키워드의 계산을 중단시키지 않도록 한다. 전체 실행 결과에는 성공·실패 건수와 실패 사유를 요약한다.

네트워크 오류, 429, 일시적 5xx는 제한된 횟수만 지수 백오프로 재시도한다. 인증 오류는 재시도하지 않고 즉시 중단한다.

## 8. 캐시와 재현성

- 검색광고 응답은 정규화 키워드와 수집시각을 키로 캐시한다.
- DataLab 응답은 키워드 묶음, 시작일, 종료일을 키로 캐시한다.
- 기본 실행에서는 같은 기간의 정상 캐시를 재사용한다.
- 강제 갱신 옵션을 제공한다.
- 결과에 조회 기간, 수집시각, 모델 버전과 원본 파일명을 기록한다.
- 원본 API 응답 전체를 결과 엑셀에 넣지 않는다.

## 10. 실행 인터페이스

최종 사용자는 하나의 명령만 실행한다.

```text
python scripts/run_yuksudang_daily_keyword_volume.py \
  --input "원본.xlsx" \
  --end-date 2026-09-01 \
  --output-dir outputs/...
```

Python 실행기가 내부적으로 Node.js 입력 추출과 결과 워크북 생성을 호출한다. 기본 종료일은 실행일이며, 테스트와 재현성을 위해 명시적으로 지정할 수 있다.

지원 옵션:

```text
--end-date YYYY-MM-DD
--store 매장명
--force-refresh
--dry-run
```

`--dry-run`은 엑셀 입력과 환경설정을 검증하고 예상 API 요청 수만 출력하며 외부 API를 호출하지 않는다.

## 11. 테스트

### Python 단위 테스트

- HMAC 서명 입력과 결과
- 검색광고 저검색량·누락값 파싱
- DataLab 날짜 누락 시 0 채움
- ratio 합 0 처리
- 최대 나머지 정수 배분
- PC·모바일·전체 30일 합계 불변조건
- 중복 키워드 캐시
- 부분 실패 격리

### 통합 테스트

- 샘플 매장 1개, 키워드 3개 입력
- 고정 API fixture로 30일 결과 생성
- 결과 JSON 스키마 검증
- 원본 시트 보존 여부 확인
- 두 결과 시트의 행 수와 핵심 합계 검증

### 실 API 검증

- 먼저 매장 1개로 인증과 응답 형식을 확인한다.
- 성공 후 전체 매장으로 확장한다.
- 비밀값과 인증 헤더가 로그에 없는지 확인한다.

### 엑셀 시각 검증

- 두 결과 시트의 헤더, 열 너비, 날짜·숫자 형식 확인
- 필터와 첫 행 고정 확인
- 잘림이나 깨진 셀이 없는지 렌더링 확인
- 수식 오류와 빈 결과 시트 여부 확인

## 12. 완료 기준

- 원본에서 모든 매장별 키워드1·2·3을 추출한다.
- 유효 키워드는 API 결과 또는 명시적 실패 상태를 가진다.
- 성공 키워드는 정확히 30일의 일간 행을 가진다.
- 성공 키워드의 PC·모바일·전체 일간 합계가 각 30일 검색량과 일치한다.
- 원본 워크북 시트와 값이 보존된다.
- 결과 엑셀의 두 신규 시트가 읽기 쉽고 검증 가능하다.
- 비밀정보가 코드, 로그, 캐시 또는 산출물에 노출되지 않는다.
