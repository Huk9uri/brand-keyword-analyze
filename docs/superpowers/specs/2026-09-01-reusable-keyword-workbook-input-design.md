# 재사용 가능한 키워드 검색량 표준 입력 설계

## 목적

사용자가 프로젝트 폴더에 일관된 형식의 엑셀 파일을 제공하면, 별도의 시트명·열 위치 지정 없이 매장별 키워드를 읽고 최근 30일의 일간 검색량 추정 결과를 생성한다.

현재 모델은 키워드를 스스로 발견하지 않는다. 사용자가 분석할 키워드를 표준 엑셀로 제공한다는 전제를 유지하며, 입력·검증·실행 방식을 고정해 반복 실행의 실수를 줄인다.

## 표준 파일 위치

실제 입력 파일은 다음 경로만 사용한다.

```text
inputs/keyword_input.xlsx
```

`inputs/` 폴더의 최신 파일을 자동 선택하지 않는다. 고정 파일명을 사용해 임시본이나 과거 파일을 잘못 읽는 위험을 방지한다.

배포용 빈 양식은 다음 경로에 둔다.

```text
templates/keyword_input_template.xlsx
```

사용자는 템플릿을 복사해 `inputs/keyword_input.xlsx`로 저장한 뒤 값을 입력한다.

## 표준 통합문서 구조

### `사용방법` 시트

- 입력 파일 위치와 실행 명령을 설명한다.
- 키워드는 매장당 최대 5개임을 명시한다.
- 6개 이상은 DataLab의 5개 그룹 제한 때문에 현재 모델의 대상이 아니며, 앵커 키워드 기반 별도 모델이 필요함을 설명한다.
- 예시 행을 삭제하고 실제 데이터를 입력하도록 안내한다.

### `키워드입력` 시트

첫 행을 헤더로 사용한다.

| 열 | 필수 여부 | 의미 |
|---|---|---|
| 매장명 | 필수 | 결과를 구분하는 매장 이름 |
| 키워드1 | 필수 열 | 첫 번째 분석 키워드 |
| 키워드2 | 선택 | 두 번째 분석 키워드 |
| 키워드3 | 선택 | 세 번째 분석 키워드 |
| 키워드4 | 선택 | 네 번째 분석 키워드 |
| 키워드5 | 선택 | 다섯 번째 분석 키워드 |

`키워드2~5` 셀은 비어 있을 수 있다. `키워드1` 열은 반드시 존재해야 하며, 각 실제 매장 행에는 최소 한 개의 유효 키워드가 있어야 한다.

추가 메모 열은 허용하지만 입력 파이프라인은 무시한다. `키워드6` 이상의 헤더가 존재하면 입력 오류로 중단한다.

## 입력 정규화 및 검증

API를 호출하기 전에 전체 입력을 검증한다.

1. `inputs/keyword_input.xlsx` 파일이 존재해야 한다.
2. `키워드입력` 시트가 존재해야 한다.
3. `매장명`, `키워드1` 헤더가 존재해야 한다.
4. 키워드 헤더는 `키워드1~5` 범위만 허용한다.
5. `키워드6` 이상의 헤더가 있으면 다음 취지의 오류를 표시한다.

   ```text
   매장당 6개 이상의 키워드는 현재 모델에서 지원하지 않습니다. DataLab 비교를 위해 앵커 키워드 기반 별도 모델이 필요합니다.
   ```

6. 매장명이 비어 있는 행은 데이터가 없는 행으로 간주한다. 다른 입력값이 있는데 매장명만 비어 있으면 오류 처리한다.
7. 동일한 매장명이 여러 행에 있으면 행 번호와 함께 오류 처리한다.
8. 실제 매장 행에 유효 키워드가 하나도 없으면 오류 처리한다.
9. 앞뒤 공백을 제거한 뒤 비어 있는 값은 빈 키워드로 처리한다.
10. 같은 매장 안에서 공백 제거·대소문자 정규화 후 같은 키워드는 최초 슬롯만 유지한다.
11. 템플릿의 예시 매장 행이 남아 있으면 실제 데이터로 오인하지 않도록 오류 처리한다.

검증 오류는 파일, 시트, 행, 열 또는 헤더를 가능한 범위에서 명시한다. 하나라도 오류가 있으면 네이버 API를 호출하지 않는다.

## 중복 처리

매장 내부 중복은 최초 등장 슬롯만 유지한다.

예:

| 입력 | 처리 |
|---|---|
| 키워드2 = 갈비탕 | 유지 |
| 키워드4 = 갈비탕 | 제거 |

서로 다른 매장에서 같은 키워드를 사용하는 경우 결과 행은 매장별로 유지하되, 검색광고 API 조회 결과는 정규화 키워드 기준으로 재사용한다.

## 실행 인터페이스

프로젝트 루트에서 다음 명령 하나로 실행한다.

```powershell
.\run_keyword_volume.ps1
```

스크립트는 다음 순서로 동작한다.

1. `.env`와 필수 네이버 API 설정 확인
2. `inputs/keyword_input.xlsx` 존재 확인
3. 표준 입력 구조 및 전체 행 검증
4. 매장 내 중복 제거
5. 네이버 검색광고 API에서 PC·모바일 최근 30일 검색량 조회
6. DataLab 일별 ratio 조회
7. 앵커 없이 키워드별 독립 정규화
8. 결과 JSON과 엑셀 생성
9. 결과 경로와 성공·미산출 건수 출력

종료일은 실행 당일이며 시작일은 종료일을 포함해 30일 전 범위로 자동 계산한다. 테스트와 재현을 위해 내부 Python CLI의 `--end-date` 옵션은 유지한다.

## 출력 위치와 파일

각 실행은 다음 형식의 고유 폴더에 저장한다.

```text
outputs/YYYYMMDD_HHMMSS/
```

주요 출력 파일은 다음과 같다.

```text
매장별_키워드_30일_일간검색량_YYYY-MM-DD.xlsx
daily_volume_results.json
input_keywords.json
```

동일 시각 폴더가 이미 존재하면 덮어쓰지 않고 충돌을 피할 수 있는 접미사를 사용한다.

## 결과 엑셀

입력 통합문서를 복사해 결과 시트를 추가한다. 원본 `사용방법`과 `키워드입력` 시트는 변경하지 않는다.

### `30일_키워드요약`

표시 열:

- 매장명
- 키워드구분
- 키워드
- PC_30일검색량
- 모바일_30일검색량
- 전체_30일검색량
- 일평균
- 최대검색일
- 최대일간검색량

`일간추정합계`, `DataLab_ratio합`, `상태`, `오류사유`는 표시하지 않는다.

### `30일_일간검색량`

표시 열:

- 매장명
- 키워드구분
- 키워드
- 검색일
- PC_30일검색량
- 모바일_30일검색량
- 전체_30일검색량
- DataLab_ratio
- PC_일간추정량
- 모바일_일간추정량
- 전체_일간추정량

`상태`, `오류사유`는 표시하지 않는다.

저검색량, DataLab 신호 없음, API 오류 등의 상세 상태는 `daily_volume_results.json`에 보존한다.

## 계산 규칙

기존 모델을 그대로 사용한다.

```text
키워드의 날짜별 추정 검색량
= 해당 키워드의 최근 30일 검색량
  × 해당 날짜 DataLab ratio
  ÷ 해당 키워드의 30일 ratio 합
```

PC와 모바일을 각각 최대 나머지 방식으로 정수 배분한다. 성공 키워드는 다음 조건을 만족해야 한다.

- 일간 행이 정확히 30개
- PC 일간추정량 합계 = PC 30일검색량
- 모바일 일간추정량 합계 = 모바일 30일검색량
- 전체 일간추정량 합계 = 전체 30일검색량

## 오류 처리

- 입력 구조 오류는 API 호출 전에 즉시 중단한다.
- 인증정보 누락은 누락된 환경변수 이름만 표시하고 값은 출력하지 않는다.
- 개별 키워드의 저검색량 또는 DataLab 신호 없음은 다른 키워드 처리를 중단하지 않는다.
- 생성 결과에 수식 오류가 있거나 결과 시트가 비어 있으면 엑셀 생성을 실패 처리한다.
- 실패 시 기존 입력 파일을 수정하거나 삭제하지 않는다.

## 테스트 및 검증

자동 테스트는 다음을 포함한다.

- 표준 템플릿에서 매장명과 키워드1~5 추출
- 빈 선택 키워드 허용
- 매장 내 중복 제거 및 최초 슬롯 유지
- 중복 매장명 거부
- 키워드 없는 매장 거부
- `키워드6` 이상 거부 및 앵커 모델 안내
- 예시 행 잔존 거부
- 검증 실패 시 API 미호출
- 실행 폴더와 결과 파일명 생성
- 기존 검색량·DataLab·일간 배분 회귀 테스트
- 결과 시트 헤더와 표시 제외 열 검증
- 성공 키워드의 30일 합계 대사
- 두 결과 시트 렌더링을 통한 시각 검증

## 범위 밖 항목

- 키워드 자동 발견 및 추천
- 네이버 플레이스 경쟁점 `keywordList` 수집
- 매장당 6개 이상의 키워드를 비교하기 위한 앵커 모델
- 대표키워드 자동 적용
- 정기 스케줄 실행

이 항목들은 표준 입력 파이프라인과 별도 기능으로 다룬다.
