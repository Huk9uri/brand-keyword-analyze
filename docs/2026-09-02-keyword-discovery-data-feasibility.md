# 외식업 매장 키워드 발굴 과제 - 데이터 수집 가능성 및 파일럿 설계

- 작성일: 2026-09-02
- 대상 프로젝트: `C:\workspace\brand_analyze`
- 대상 업종: 국밥·설렁탕 등 외식업 매장
- 문서 상태: 구현 전 기획 및 데이터 소스 1차 검증 완료
- 후속 원칙: 사람 검증으로 판정 기준을 확정한 뒤 경쟁점 데이터 수집을 자동화한다.

## 1. 과제의 목적

기존 검색량 모델은 사용자가 입력한 키워드의 최근 30일 검색량을 계산한다. 본 과제는 이보다 앞 단계인 **키워드 후보 자동 발굴과 추천**을 다룬다.

지역명·역명·랜드마크 조합에 한정하지 않고, 네이버와 같은 검색 포털에서 외식 매장이 노출을 확보할 수 있는 다음 두 유형의 키워드를 찾는다.

### 1.1 빈집 키워드

검색수요와 외식 방문 가능성은 존재하지만, 상위 검색 결과에서 직접 경쟁점의 점유와 전문 최적화가 상대적으로 약해 자사 매장이 진입할 여지가 있는 키워드다.

### 1.2 핵심 경쟁 키워드

검색수요와 사업 가치가 크고 경쟁점의 선점도 강하지만, 국밥·설렁탕 업종이 반드시 노출 경쟁에 참여해야 하는 키워드다.

### 1.3 제외 키워드

검색량이 있더라도 매장의 실제 메뉴·서비스·영업 조건과 맞지 않거나, 외식 방문으로 연결될 가능성이 낮은 키워드다.

예시:

```text
설렁탕 밀키트
국밥 택배
곰탕 레시피
설렁탕 칼로리
국밥집 알바
업소용 사골육수
```

## 2. 전체 접근 방식

처음부터 정답 키워드만 생성하려 하지 않고, 실제 관찰 데이터에서 후보를 넓게 모은 뒤 단계적으로 검증한다.

```text
관찰 기반 후보 발굴
→ 출처 기록
→ 중복 제거·표현 정규화
→ 유사 표현의 의도군 구성
→ 비외식 의도·사실 불일치 제거
→ 검색량 확인
→ 검색 결과와 경쟁 구도 분석
→ 빈집·핵심 경쟁 분류
→ 매장별 대표키워드 5개 선정
```

지역명·메뉴·상황·고객·시설을 무제한 조합하면 실제로 검색되지 않는 가짜 키워드가 폭증한다. 따라서 검색광고 연관키워드, 리뷰, 검색 결과, 경쟁점 정보 등에서 실제로 관찰된 표현을 우선 사용하고 조합 생성은 제한적으로 적용한다.

## 3. 후보 발굴 범위

후보는 기존의 지역·역·랜드마크 외에 외식 고객의 메뉴, 목적, 상황, 고객 유형, 매장 속성 및 대체 수요까지 포함한다.

| 유형 | 예시 |
|---|---|
| 메뉴·제품 | 국밥, 설렁탕, 갈비탕, 수육, 냉면, 도가니탕 |
| 식사 목적 | 아침식사, 점심, 혼밥, 가족식사, 단체식사 |
| 문제 해결 | 해장, 속풀이, 보양식, 든든한 한 끼 |
| 시간·상황 | 출근 전 식사, 늦은 저녁, 비 오는 날 음식 |
| 고객·동행 | 직장인 점심, 아이와 식사, 부모님 식사, 회식 |
| 시설·서비스 | 주차 가능, 포장, 배달, 단체석, 가성비 |
| 대체·인접 수요 | 곰탕, 순대국, 감자탕, 백반, 찌개, 한식 |

## 4. 모델과 LLM의 역할

본 문서에서 `모델`은 LLM 하나를 뜻하지 않는다. 데이터 수집, 검증, 점수화 및 판정 로직 전체를 의미한다.

### 4.1 수집 모듈

- 검색광고 연관키워드 수집
- 검색량과 클릭 지표 수집
- 검색 결과 및 순위 수집
- 경쟁점 기본정보와 `keywordList` 수집
- 자사·경쟁점 리뷰 수집
- 자사 매장·메뉴·영업 조건 연결

### 4.2 규칙·통계 기반 평가 모듈

- 검색 의도 게이트
- 자사 매장 적합성
- 검색수요 점수
- 직접 경쟁점 점유율
- 전문 최적화 매장 비율
- 현재 노출 가능성
- 빈집·핵심 경쟁 분류

### 4.3 LLM 보조 모듈

LLM은 다음과 같이 언어의 의미를 해석하는 부분에 제한적으로 사용한다.

- 리뷰에서 메뉴·식사 상황·고객 표현 추출
- `속풀이`, `해장`, `숙취해소`와 같은 유사 표현 군집화
- 외식·정보·쇼핑 의도 분류 보조
- 검색어와 매장 메뉴·서비스의 의미 적합성 보조 판정
- 추천 사유의 자연어 설명

검색량, 순위, 경쟁점 수, 채택률 및 최종 점수는 관측 데이터와 설명 가능한 규칙으로 계산한다.

## 5. 검색 의도 게이트

방문 의도는 가점을 주는 독립 항목보다는 잘못된 후보가 평가 단계에 진입하지 못하게 하는 필수 자격 검증으로 사용한다.

| 분류 | 예시 | 처리 |
|---|---|---|
| 외식 의도 | 국밥 맛집, 해장, 혼밥, 아침식사 | 유지 |
| 혼합 의도 | 설렁탕, 곰탕, 냉면 | 검색 결과 구성으로 판단 |
| 비외식 의도 | 밀키트, 레시피, 칼로리, 택배 | 제외 |

혼합 의도는 검색 결과에서 음식점·플레이스가 차지하는 비율과 쇼핑·정보성 문서의 비율을 이용해 판정한다.

```text
외식 결과 비율
= 분석한 검색 결과 중 음식점·플레이스 결과 수
  ÷ 분석한 전체 결과 수
```

## 6. 빈집·핵심 경쟁 판정 구조

초기에는 임의의 단일 임계치로 판정하지 않는다. 절대 하한, 후보군 내 상대 분위수, 사람이 판정한 파일럿 정답을 결합해 기준을 보정한다.

### 6.1 빈집 후보 자격

```text
검색량 측정 가능
AND 검색 의도 게이트 통과
AND 자사 매장 적합성 기준 통과
AND 메뉴·서비스·영업 조건의 사실 충돌 없음
```

자격 통과 후 다음 요소를 결합한다.

```text
빈집점수
= 검색수요
+ 매장 적합성
+ 낮은 직접 경쟁점 점유율
+ 낮은 전문 최적화 매장 비율
+ 현재 노출 가능성
```

### 6.2 핵심 경쟁 후보

```text
검색수요 높음
AND 외식 의도 통과
AND 매장 적합성 높음
AND 직접 경쟁점 점유율 또는 전문 최적화 비율 높음
```

대표키워드 5개를 빈집과 핵심 경쟁의 고정 비율로 나누지 않고, 매장별 기회점수에 따라 유동적으로 선정하되 각 추천에 유형을 명시한다.

### 6.3 임계치 설정 원칙

- 검색량 수치 미제공, 판매하지 않는 메뉴, 지원하지 않는 서비스 등은 절대 기준으로 제외한다.
- 수요·경쟁도는 동일 매장 또는 유사 상권 후보군 내 분위수로 비교한다.
- 상위 10개 중 2개 이하와 같은 고정 규칙은 확정 기준으로 사용하지 않는다.
- 상위 그룹과 비교 그룹의 차이를 측정한다.
- 파일럿에서 사람이 만든 `빈집 / 핵심 경쟁 / 일반 / 제외 / 보류` 판정과 자동 점수를 비교해 임계치를 확정한다.
- 대표키워드는 5개뿐이므로 초기에는 재현율보다 정밀도를 우선한다.

### 7.2 검색광고 연관키워드

현재 검색광고 API의 `/keywordstool` 응답에는 다음 필드가 존재한다.

- `relKeyword`
- `monthlyPcQcCnt`
- `monthlyMobileQcCnt`
- `compIdx`
- PC·모바일 평균 클릭 수와 클릭률
- `plAvgDepth`

`설렁탕` 소량 검증에서 487개 연관 행이 반환됐다. 후보에는 `사골곰탕`, `갈비탕`, `곰탕맛집`, `돼지국밥`과 함께 `업소용레시피`, `설렁탕프랜차이즈`, `식자재쇼핑몰` 같은 비외식 노이즈도 포함됐다.

현재 코드는 요청 키워드의 검색량만 골라 사용하므로, 후보 발굴에서는 전체 `relKeyword` 행을 별도 저장해야 한다.

공식 문서:


### 7.3 네이버 공식 검색 API

현재 네이버 애플리케이션 키로 지역 검색과 블로그 검색 API가 모두 정상 호출됐다.

지역 검색 API는 업체명, 카테고리, 설명, 주소, 좌표 및 링크를 반환한다. 다만 한 번에 최대 5개 결과만 제공하고 실제 네이버 지도·플레이스 전체 순위를 대체하지 못하므로, 경쟁점 발견보다 카테고리와 주소 보강에 적합하다.

```text
https://developers.naver.com/docs/serviceapi/search/local/local.md
```

블로그 검색 API는 제목, 본문 요약, 작성일, 블로그명과 링크를 제공한다.

```text
https://developers.naver.com/docs/serviceapi/search/blog/blog.md
```

### 7.5 자사 매장·메뉴 DB

자사 매장 마스터에는 다음 정보가 존재한다.

- 브랜드·매장명·주소
- 주중·주말 영업시간
- 요일별 영업 여부
- 주차 가능 여부와 주차 대수
- 좌석·테이블 수
- 매장 상태

품목 마스터와 메뉴 선택 데이터도 존재한다. 다만 전체 품목 마스터가 실제 개별 매장에서 판매되는 메뉴를 의미하지 않으므로, 매장별 판매·POS 이력 또는 메뉴 선택 데이터와 연결해야 한다.

### 7.7 경쟁점 `keywordList`

네이버 플레이스 페이지 원문의 초기 데이터에서 다음 구조가 확인됐다.

```json
"keywordList": ["선릉역", "점심", "밥집", "한식", "만두"]
```

현재 경쟁점용 파서와 저장 테이블은 없다. 자사 데이터의 `smartplace_keyword_all`은 유입 검색어 데이터이며 경쟁점이 설정한 `keywordList`와 다르다.

권장 저장 구조:

```text
place_id
keyword
collected_at
parser_version
source_url
parse_status
```

## 8. 파일럿의 정의

파일럿은 전체 매장 시스템을 만들기 전에 소수 매장을 대상으로 후보 발굴과 판정 기준의 유효성을 검증하는 소규모 실험이다. 운영을 영구적으로 수동 처리하겠다는 의미가 아니다.

### 8.1 권장 범위

```text
육수당 매장 5개
× 최초 후보 30~50개
→ 검색량·의도·적합성으로 매장당 약 10개 선별
→ 매장당 핵심 후보 5개 심층 조사
→ 후보당 상위 10개 + 비교 그룹 10개 조사
```

최대 검색 결과 행:

```text
5개 매장 × 후보 5개 × 검색 결과 20개 = 500행
```

동일 플레이스 ID는 중복 제거하고 상세정보와 `keywordList`를 한 번만 조사한다.

### 8.2 파일럿의 목적

1. 확보한 소스에서 새로운 외식 키워드가 실제로 발견되는지 확인한다.
2. 비외식·무관 키워드를 제대로 제거하는지 확인한다.
3. 빈집과 핵심 경쟁을 사람이 납득할 수 있게 구분하는지 확인한다.
4. 경쟁점 데이터 중 실제로 유효한 필드를 확인한다.
5. 사람이 만든 정답과 자동 점수의 일치도를 측정한다.
6. 기준 확정 후 반복 수집을 자동화한다.

## 9. 파일럿 수집 항목

### 9.1 검색어별 노출 결과

| 필드 | 용도 |
|---|---|
| 검색어 | 분석 시장 식별 |
| 검색일시 | 순위 변동 추적 |
| 조회 위치 | 위치 조건 통제 |
| 기기 환경 | PC·모바일 조건 구분 |
| 노출 순위 | 상위·비교 그룹 분리 |
| 플레이스 ID | 매장 중복 제거와 연결 |
| 매장명 | 결과 확인 |
| 카테고리 | 직접 경쟁점 판정 |
| 자사 여부 | 자사 현재 위치 확인 |
| 광고 여부 | 자연 노출과 광고 분리 |
| 거리 | 위치 영향 참고 |

상위 그룹은 1~10위, 비교 그룹은 11~20위로 시작한다. 이 구간은 확정 규칙이 아니라 파일럿 표본 설계다.

### 9.2 경쟁점 기본정보

- 플레이스 ID
- 매장명
- 업종·카테고리
- 주소·좌표
- 대표메뉴와 가격
- 매장 소개
- 영업시간
- 주차·포장·배달·예약·단체 이용
- 방문자 리뷰 수
- 블로그 리뷰 수
- `keywordList`

### 9.3 리뷰 표본

모든 경쟁점의 전체 리뷰를 수집하지 않는다. 상위권 직접 경쟁점, 여러 검색어에 반복 등장하는 경쟁점, `keywordList`가 후보와 일치하는 경쟁점 및 자사와 메뉴·상권이 유사한 경쟁점을 우선한다.

권장 표본:

```text
방문자 리뷰: 경쟁점당 최근 30~50개
블로그 리뷰: 경쟁점당 최근 20~30개
```

리뷰에서는 감성 자체보다 반복되는 메뉴, 식사 목적, 상황, 고객 유형과 시설·서비스 표현을 추출한다.

### 9.4 사람의 판정 데이터

한 행은 `매장 × 후보 키워드`로 구성한다.

| 판정 필드 | 값 |
|---|---|
| 외식 의도 | 외식 / 혼합 / 비외식 |
| 자사 적합성 | 적합 / 조건부 / 부적합 |
| 경쟁 유형 | 직접 / 간접 / 비경쟁 |
| 시장 유형 | 빈집 / 핵심 경쟁 / 일반 / 제외 / 보류 |
| 추천 여부 | 추천 / 미추천 |
| 판정 확신도 | 높음 / 보통 / 낮음 |
| 판정 사유 | 자유 기재 |

## 10. 수집 항목별 가능성

| 우선 항목 | 가능성 | 현재 준비도 | 필요한 보완 |
|---|---|---|---|
| 검색어별 상위·비교 순위 | 가능 | 중간 | 기존 순위 수집기를 전체 결과 저장 방식으로 확장 |
| 플레이스 ID·카테고리·대표메뉴 | 가능 | 중간 | 카테고리는 공식 API, ID·메뉴는 상세 수집 보완 |
| 경쟁점 `keywordList` | 가능 | 낮음 | 전용 파서와 스냅샷 테이블 신규 개발 |
| 영업시간·시설·서비스 | 가능 | 중간 | 자사는 DB 보유, 경쟁점은 상세 수집 필요 |
| 방문자 리뷰 | 가능 | 높음 | 기존 수집기를 경쟁점 ID 목록에 적용 |
| 블로그 리뷰 | 가능 | 높음 | 기존 DB와 공식 검색 API 활용 |
| 검색량·광고 경쟁도 | 즉시 가능 | 높음 | 기존 검색량 모듈과 연관키워드 원본 재사용 |
| 사람의 빈집·경쟁 판정 | 즉시 가능 | 높음 | 표준 판정 엑셀 또는 CSV 작성 |

## 11. 실제 권장 수집 순서

분석 중요도와 실제 실행 순서는 다르다. 비용이 낮은 데이터로 후보를 먼저 줄인 뒤 경쟁점 상세 데이터를 수집한다.

### 11.1 1차 - 저비용 후보 선별

1. 검색광고 연관키워드 수집
2. 기존 방문자·블로그 리뷰에서 표현 추출
3. 기존 운영팀 후보 결합
4. 중복·유사어 정규화와 의도군 구성
5. 검색량 확인
6. 자사 메뉴·영업 조건 검증

```text
매장당 최초 30~50개 → 약 10개
```

### 11.2 2차 - 경쟁 구도 수집

1. 후보별 검색 결과 1~20위 수집
2. 플레이스 ID와 카테고리 확보
3. 직접·간접 경쟁점 분류
4. 경쟁점 `keywordList` 수집

```text
매장당 약 10개 → 심층 후보 약 5개
```

### 11.3 3차 - 심층 검증

1. 핵심 경쟁점의 대표메뉴·영업시간·시설 수집
2. 최근 방문자 리뷰 표본 수집
3. 블로그 리뷰 표본 수집
4. 사람이 빈집·핵심 경쟁 판정
5. 자동 점수와 사람 판정 비교

## 12. 우선 개발이 필요한 데이터 공백

검색량, 자사 매장 정보, 방문자 리뷰와 블로그 리뷰는 기존 기반을 재사용할 수 있다. 파일럿의 핵심 데이터 공백은 다음 두 가지다.

1. 기존 순위 수집기를 `검색 결과 1~20위 전체 저장` 방식으로 확장
2. 플레이스 ID별 `keywordList`와 기본정보를 저장하는 상세 수집기 추가

## 13. 후속 진행 순서

```text
1. 파일럿 5개 매장 선정
2. 사람 판정용 표준 양식 확정
3. 후보 발굴 소스와 출처 스키마 확정
4. 검색 결과 1~20위 수집 구조 설계
5. 경쟁점 keywordList·기본정보 수집 구조 설계
6. 파일럿 데이터 수집
7. 사람이 빈집·핵심 경쟁 판정
8. 판정 기준과 임계치 확정
9. 자동 수집 및 자동 점수화 구현
10. 전체 매장 확장
```

## 14. 한 문장 요약

> 검색광고 연관키워드, 기존 리뷰, 자사 메뉴·매장 정보와 검색 결과 경쟁점 데이터를 결합해 후보를 넓게 발굴한 뒤, 5개 매장 파일럿에서 사람이 빈집·핵심 경쟁을 판정해 기준을 확정하고, 그 기준을 토대로 경쟁점 순위와 `keywordList` 수집을 자동화한다.
