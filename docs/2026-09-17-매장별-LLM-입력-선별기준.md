# 매장별 LLM 입력 선별 기준

## 확정 운영 단위

사용자 결정에 따라 **매장 하나당 LLM 호출 한 번**으로 구성한다. 이 문서는 호출에 포함할 정보의 선별 기준을 정리한 결과다. 현재 입력 생성 코드에 아래 축소안을 적용하거나 유료 호출을 실행하지는 않았다.

판단 목적은 해당 매장에서 판매 근거가 있고 검색량이 확인되며 상위 20위에 미노출인 키워드 가운데 먼저 시험할 후보와 그 이유를 제안하는 것이다. 검색 결과 전체를 재분석하거나 새로운 메뉴→키워드 연결을 만드는 작업은 이번 호출의 목적에 포함하지 않는다.

## 실제 입력 크기 확인

수원인계점 `000110`의 입력은 키워드 28개를 포함하며 약 9.4만 자다. `json.dumps(..., ensure_ascii=False)` 직렬화 기준으로 주요 값의 크기를 확인했다. 아래 항목의 키 이름·구분자 등은 별도이므로 단순 합계가 전체 크기와 정확히 일치하지 않는다.

| 항목 | 문자 수 | 확인 내용 |
|---|---:|---|
| 키워드별 검색 결과 목록 | 43,313 | 광고 제외 업체명·업체 ID·업종·순위의 반복 |
| 근거 문장 facts | 5,807 | 구조화된 판매·검색량·판정 자료를 문장으로 다시 기록 |
| 매장별 키워드에 붙인 변화 자료 | 6,833 | 별도 comparison과 같은 내용 반복 |
| 별도 comparison | 7,072 | 비교 상태와 변화 자료 포함 |
| 미연결 메뉴 상세 | 6,048 | 이 매장은 UNMAPPED_MENU 46개 기록 |
| 연결 메뉴별 판매 자료 | 4,653 | 같은 POS 메뉴가 여러 키워드에 반복 포함될 수 있음 |

전체가 큰 원인은 매장 수뿐 아니라 **한 매장 안에서도 상세 검색 결과와 동일 근거가 반복되기 때문**이다.

## 항목별 결정

| 정보 | 추천 호출에 제공할 내용 | 상세 보고서에 보존할 내용 | 이유 |
|---|---|---|---|
| 매장 식별·분석 기간 | 매장 코드·이름, 기간, 기준 시각을 한 번 제공 | Place ID·좌표·원본 출처 | 다른 매장 혼동 방지에 필요한 식별만 반복 없이 전달 |
| 후보 키워드 | 유효 후보 전부의 검색량·판매량·매출·관측일·메뉴 참조 | 원본 결과 행 | LLM 입력 이전에 상위 몇 개로 잘라 추천을 편향시키지 않음 |
| 이미 노출된 키워드 | 키워드·현재 순위·검색량·판매 근거·메뉴 참조 | 검색 결과 전체 | 기존 주력 표현 및 동일 메뉴의 노출 차이 비교에 필요 |
| 보류 키워드 | 키워드·보류 사유·관측일·확정된 판매 근거 | 실패 진단·원본 관측 | 실패를 미노출이나 수요 없음으로 오인하지 않도록 유지 |
| 실제 POS 메뉴 | 메뉴별 판매량·매출을 공통 메뉴 표에 한 번 제공, 키워드에서 참조 | 원본 메뉴 코드별 행 | 실제 판매 근거와 메뉴 간 중복을 모두 보존 |
| 메뉴 연결 규칙 | 실제 연결 메뉴 ID와 적합성 확인 조건 | 판매되지 않은 연결 가능 메뉴 목록 | 현재 매장의 후보 판단에 직접 쓰는 연결만 전달 |
| facts 근거 문장 | 중복 문장을 제거하고 구조화된 행의 근거 ID 사용 | 코드가 원자료에서 인용 문장을 생성 | 모델이 같은 숫자를 두 번 읽거나 원문을 다시 복사할 필요 없음 |
| 경쟁 검색 결과 | **기본 추천 호출에서 업체 목록 제외** | 업체명·업종·ID·순위 전체 | 목록만으로 경쟁 강도나 진입 난도를 판단할 수 없고 입력 비중이 큼 |
| 미연결 메뉴 | 사유별 기록 수·판매액·수량, 매핑 미검토 상태 | 개별 메뉴명·코드·판매 기록 전체 | 추천 가능한 키워드로 연결되지 않은 자료이며 무단 신규 연결 방지 |
| POS 품질 | 해당 매장의 관측일 수·공백일·최근 관측일, 전체 적재 상태의 핵심 주의사항 | 다른 매장 품질 상세 | 판매 감소나 현재 판매 중이라고 잘못 단정하는 것을 방지 |
| 이전 대비 변화 | 비교 가능 여부·사유를 한 번, 실제 변경 항목만 제공 | UNCHANGED를 포함한 전체 내역 | 현재 값은 키워드 표에 있으므로 동일 값을 재전달할 필요 없음 |
| 스냅샷 ID·파일 경로 | 간결한 근거 ID만 제공 | 근거 ID→원본 스냅샷·파일 연결표 | 추적 가능성은 코드에서 보장하고 내부 식별자 반복을 줄임 |

## 경쟁 결과 처리

이번 추천은 판매 근거·검색량·대상 매장 노출 여부를 비교하는 작업이다. 경쟁 업체 목록 전체가 없어도 수행할 수 있다. 따라서 상위 몇 개 업체만 임의로 잘라 넣기보다 기본 입력에서 목록을 제외한다.

대상 매장의 유효 순위·상위 20위 미노출 판정·관측일·관측 유효성은 반드시 유지한다. 기존 코드가 확정한 판정을 사용하며, 업체 목록을 뺐다는 이유로 관측의 품질 조건을 완화하지 않는다.

경쟁 업체 정보는 삭제하지 않고 상세 결과에 보존한다. 향후 경쟁 메뉴나 플레이스 정보 개선을 별도 분석할 때 사용한다. 기본 프롬프트에서는 경쟁이 약하다거나 진입이 쉽다는 결론을 요구하지 않는다.

## 미연결 메뉴 처리

미연결 메뉴 전체를 읽혀 LLM이 임의의 검색 키워드로 변환하게 하지 않는다. 기존 메뉴→키워드 연결 목록에서 검증된 조합만 추천한다.

집계는 원본 메뉴 판매 행 단위로 수행하고 키워드별로 중복된 매출을 합산하지 않는다. 사유별 기록 수는 고유 메뉴 수와 구분한다. 비율을 추가할 경우 동일 매장·기간·중복 제거 기준의 분모가 확인될 때만 계산한다. 모호한 매핑의 중복 가능성이 있으면 금액 집계도 보류한다.

모델에는 연결되지 않은 판매 기록이 남아 있으므로 추천 범위가 전체 판매 메뉴를 포괄하지 않는다는 점을 전달한다. 상세 메뉴는 검토 목록에 그대로 남긴다.

## 권장 입력 구조

1. `store`: 매장 코드·이름
2. `analysis`: 기간·기준 시각·전체 및 매장 데이터 상태
3. `menus`: 실제 연결 메뉴별 판매 근거, 중복 없이 한 번
4. `keywords`: 후보·기노출·보류별 키워드, 메뉴 참조, 판매 합계, 검색량·상태·관측일, 순위·상태·관측일, 연결 적합성 주의사항
5. `unmapped_summary`: 미연결 사유별 집계와 검토 필요 여부
6. `changes`: 비교 가능 여부와 실제 변경 내역
7. `definitions`: 전국 검색량, 상위 20위 판정, 중복 합산 금지 등 공통 해석 규칙

응답은 선택한 키워드/근거 ID와 선정 이유·확인 사항·다음 행동을 받는 방향으로 후속 보완한다. 인용 수치는 코드가 붙인다. 이는 기존 facts 원문 복사와 숫자 일괄 금지 규칙도 함께 수정해야 하므로 단순 필드 삭제만으로 적용하지 않는다.

## 적용 후 검증 기준

- 기존 후보·기노출·보류 조합 수와 ID가 동일해야 한다.
- 키워드별 판매 합계와 실제 메뉴 연결이 원자료와 일치해야 한다.
- 원본 관측일·보류 사유가 유지돼야 한다.
- 경쟁 결과와 미연결 메뉴 상세는 보고서·원자료에서 계속 조회할 수 있어야 한다.
- 같은 입력으로 축소 전후의 추천 근거·누락·토큰·비용을 비교한다.
- 크기 절감률은 축소 코드를 적용한 결과로 측정한다. 현재 단계에서 목표 문자 수나 절감률을 확정하지 않는다.
