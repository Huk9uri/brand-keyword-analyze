# 공유 순위 관측 구현 및 UC 검증 결과

## 구현

현재 5개 매장·메뉴 5개의 수집 큐 25건을 고유 관측 5건으로 묶는다.
후보 ID가 가장 작은 대표 작업으로 기존 순위 스냅샷을 저장하고, 실행 영수증의
`shared_observations`에 작업 키·검색어·원천 매장·기기·프로필과 후보별 참조 25건을 기록한다.
스냅샷 원문을 매장 수만큼 복제하지 않는다. 일반 순위 CLI 및 과거 매장별 관측은 유지한다.

원천 설정의 `rank_runs`에 새 실행 영수증의 `run_id`, `profile`, `time_offset`,
`shared_observations`를 함께 넣으면 재수출 시 `rank_links`가 생성된다.
실행·작업 키·검색어·기기·프로필 및 후보·매장 식별을 검사한다. 실행 중단으로 저장되지 않은
작업에는 참조가 생기지 않는다. 미래 원천은 선택하지 않고 최신 실패·PARTIAL도 그대로 선택해
검토필요로 남긴다. 정상이고 신선하며 충분한 깊이가 확인된 공유 관측은 재수집하지 않는다.

`rank_links`는 동결 입력과 평가 저장의 input_manifest_json에 보존하므로 신규 DDL은 없다.
실제 DB 공유 관측 적재와 재수출의 운영 통합 검증은 아직 수행하지 않았다.

## 실제 확인

- 과거 실행 `f722e19d-cfbc-487b-a2b5-a9f4884b03b3`를 SELECT로 재확인: LOAD_TIMEOUT 5건.
- 최초 UC 시도는 Chrome 152와 드라이버 153 불일치로 검색 전 실패했다.
  설치 실행 파일에서 버전을 읽어 드라이버를 맞추도록 수정했다.
- 수정 후 `설렁탕` 1건을 좌표 없는 모바일 통합검색에서 수집했다.
- 실행 ID: `c46c4679-837d-47f5-99a0-4a40e4cacfea`.
- 결과: 카드 16개, 광고 6개, 자연순위 10개, 명시적 끝 없음, PARTIAL.
- 자동 재시도 0회. 로컬 증거만 저장했으며 DB에는 적재하지 않았다.
- 산출물: `outputs/shared-rank-uc-smoke-c46c4679-837d-47f5-99a0-4a40e4cacfea/`.
  `plan.json`은 관측 5건·참조 25건, `receipt.json`은 실제 시도한 메뉴 1건의 영수증이다.
  이 로컬 영수증은 DB에 스냅샷이 없으므로 운영 원천 설정에 추가하면 안 된다.

## 검증 및 다음 단계

관련 자동 테스트 425개 통과. 공유 참조 5개 매장 연결, 매핑 불일치 거절,
원천 재수출, 최신 실패 우선, PARTIAL 재수집, 기존 수집 회귀를 포함한다.

통합검색의 자연순위 20개 확보는 여전히 미완료다. UC 전환이 결과 목록 깊이를 늘리지는 않았다.
메뉴 5개 확대와 평가 DB 적재는 진행하지 않았다. 다음 단계는 순위 원천·목표 깊이의 재검토다.
별도 플레이스 목록을 채택하려면 통합검색과 구분되는 프로필과 비교 검증이 필요하며,
보안 확인이 나타나면 사용자 확인 후 정상 접근 여부를 확인해야 한다.
현재 10개 결과를 임의로 SUCCESS 또는 20위까지 미노출로 바꾸지 않는다.
